# PDF 리더 1단계 설계 (2026-10-13)

문라이트(themoonlight.io)의 논문 읽기 기능을 참고해 논문 뷰어를 다시 만든다. 전체는 네 단계이고
이 문서는 서버 없이 되는 1단계만 다룬다.

| 단계 | 내용 | 서버 |
|---|---|---|
| 1 | 뷰어 기본기, 원문 위 표시, 목차·미리보기·인용 카드 | 불필요 |
| 2 | AI 호출 창구, 1:1 대응 번역, 선택 설명 | Supabase Edge Function |
| 3 | 요약, 채팅, 자동 하이라이트 | 2단계 창구 |
| 4 | 논문 라이브러리, 추천 | 2단계 창구 + 검색 API |

AI 비용 방식(무료 한도, 유료, 사용자 키)은 2단계 설계 때 정한다.

## 1. 목표

지금 뷰어는 화면이 둘로 나뉘어 있다. "원문 보기"에서는 PDF가 그대로 보이지만 형광펜·메모·용어
표시가 안 되고, "텍스트로 보기"에서는 표시가 되지만 그림·표·수식·단 배치가 사라진다. 읽다가
표시하려면 화면을 바꿔야 한다.

1단계의 목표는 **PDF 원문 한 화면에서 모든 기능이 동작하는 전체 화면 리더**다.

성공 기준:

| # | 기준 | 확인 방법 |
|---|---|---|
| S1 | 표시(형광펜·용어 밑줄·검색 결과)가 원문 글자 위에 정확히 놓인다 | 시험 논문 묶음에서 위치 오차 측정(§7.1) |
| S2 | 기존 형광펜·메모가 새 리더에서 그대로 보인다 | 옛 뷰어에서 남긴 기록을 새 리더로 열어 확인 |
| S3 | 용어 표시는 옛 뷰어와 같은 용어를 잡는다 | `scripts/viewer-eval.js` 결과가 나빠지지 않음 |
| S4 | 인용 카드가 틀린 문헌을 보여 주지 않는다 | 시험 논문에서 정밀도 측정(§7.2) |
| S5 | 375px 폭에서 읽기·용어 카드·형광펜·메모가 된다 | 브라우저 확인 |
| S6 | 실패는 사용자에게 문구로 보인다(무음 실패 0) | §6의 각 경우 확인 |

## 2. 범위

넣는 것:

- 전체 화면 리더(도구 막대, 왼쪽 목차·쪽 패널, 오른쪽 용어·메모 패널)
- 원문 위 형광펜 4색, 메모, 복사, 사전에서 찾기
- 원문 위 용어 밑줄과 카드
- 본문 검색
- 목차(PDF 내장 목차, 없으면 제목 추정), 쪽 축소 그림
- 인용 카드, Fig./Table/Section/Eq. 미리보기, 이동 후 돌아가기
- 외부 서지 조회("자세히"를 눌렀을 때만)
- 휴대폰·좁은 화면, 키보드

넣지 않는 것:

- 번역, 선택 설명, 요약, 채팅, 자동 하이라이트(2~3단계)
- 논문 라이브러리와 추천(4단계). 최근 문서 목록은 지금 수준으로 유지
- 펜으로 그리기, 도형 주석
- "텍스트로 보기" 화면. 없앤다
- 저장 형식과 데이터베이스 변경

유지하는 것:

- PDF를 열지 않았을 때의 첫 화면(파일 끌어다 놓기, 파일 선택, 최근 문서, 글 붙여넣기 분석)
- 용어 찾기 로직과 그 테스트
- 저장 계층(`assets/pdf-annotations.js`, `assets/viewer-storage.js`)

## 3. 화면과 동작

### 3.1 첫 화면

지금처럼 사이트 메뉴가 있는 일반 페이지다. PDF를 열면 `#doc=<문서 지문>`이 주소에 붙고 전체 화면
리더로 전환된다. 브라우저 뒤로 가기는 첫 화면으로 돌아온다. 붙여넣은 글의 용어 분석은 첫 화면에서
지금 방식대로 동작한다.

### 3.2 리더

- **도구 막대(위, 한 줄)**: 닫기, 문서 제목, 쪽 번호 입력과 전체 쪽 수, 축소·확대·너비 맞춤·쪽
  맞춤, 본문 검색(입력, 이전, 다음, 건수), 용어 표시 켜기/끄기, 왼쪽 패널 여닫기, 오른쪽 패널 여닫기.
- **왼쪽 패널**: 탭 "목차"와 "쪽". 목차 항목을 누르면 그 위치로 이동한다. "쪽"은 축소 그림 목록이고
  지금 보는 쪽이 강조된다.
- **가운데**: 세로로 이어진 쪽. 보이는 쪽과 앞뒤 2쪽만 그린다.
- **오른쪽 패널**: 탭 "용어"와 "메모". "용어"는 지금 보는 쪽의 용어를 위에, 문서 전체 용어를
  아래에 둔다(분야 필터, 패널 내 검색, 숨긴 용어 복원은 옛 뷰어와 같다). "메모"는 형광펜·메모
  목록이고 누르면 그 위치로 이동한다.

패널을 연 상태와 확대 배율은 브라우저에 기억한다.

### 3.3 원문 위에서 하는 일

- **글자 드래그**: 선택 위에 도구가 뜬다. 형광펜 4색(노랑·초록·분홍·파랑), 메모, 복사, 사전에서
  찾기. "사전에서 찾기"는 선택한 말로 용어 사전을 검색해 오른쪽 패널에 결과를 보여 준다.
- **형광펜 누르기**: 색 바꾸기, 메모 고치기, 삭제.
- **용어 밑줄**: 옅은 점선. 같은 용어는 쪽마다 처음 한 번만 표시한다. 마우스를 올리면 한 줄 정의
  카드, 누르면 오른쪽 패널에 자세한 풀이. 카드에서 "이 용어 숨기기"를 할 수 있다.
- **인용 표시**([12], [3–5], (Kim et al., 2020) 등): 마우스를 올리면 참고문헌 목록의 해당 문구를
  담은 카드. 카드의 "자세히"를 누르면 외부 서지 조회 결과(제목, 저자, 연도, 학술지, 초록, 링크)를
  카드 안에 보여 준다. 인용 표시를 누르면 참고문헌 목록의 그 항목으로 이동한다.
- **Fig./Table/Section/Eq. 참조**: 마우스를 올리면 대상 위치를 잘라 보여 주는 미리보기 창, 누르면
  그 위치로 이동.
- **이동 후**: 목차·인용·참조로 이동하면 "돌아가기" 버튼이 8초 동안 뜬다. 누르면 읽던 자리로
  돌아온다.

### 3.4 키보드

| 키 | 동작 |
|---|---|
| Ctrl+F | 본문 검색 입력으로 |
| Enter / Shift+Enter (검색 입력에서) | 다음 / 이전 결과 |
| Ctrl + `+` / `−` / `0` | 확대 / 축소 / 너비 맞춤 |
| ← → , PageUp PageDown | 쪽 이동 |
| `[` , `]` | 왼쪽 / 오른쪽 패널 여닫기 |
| Esc | 열린 카드·도구 닫기, 없으면 리더 닫기 |

입력란에 초점이 있을 때는 글자 키 단축키가 동작하지 않는다.

### 3.5 좁은 화면(폭 768px 미만)

좌우 패널은 아래에서 올라오는 서랍이 된다. 도구 막대는 닫기, 쪽 번호, 검색, 패널 버튼만 남기고
나머지는 "더보기"에 넣는다. 마우스 올리기가 없으므로 용어·인용·참조는 한 번 누르면 카드가 뜨고,
카드 안의 "자세히" 또는 "이동"으로 다음 동작을 한다.

## 4. 구성

### 4.1 기존 코드

`assets/viewer.js`(4,275줄)는 용어 찾기 로직(약 1,800줄, 순수 함수)과 화면 코드(약 2,400줄)가 한
파일에 있다. 로직 부분을 내용 변경 없이 `assets/term-match.js`로 떼어낸다. `viewer.js`와 테스트는
그 파일을 불러 쓰도록만 바꾼다. 새 리더가 옛 뷰어를 대체하면 `viewer.js`의 화면 코드는 지운다.

### 4.2 새 파일

`assets/reader/` 아래에 둔다. 계산만 하는 파일은 브라우저 전역과 `module.exports`를 겸해
`tests/*.test.js`에서 `require`로 검증한다(지금 `viewer.js`와 같은 패턴).

| `text-map.js` | 쪽의 글자 조각을 읽기 순서로 이어 쪽 글(문자열)과 글자별 상자를 만든다 | `term-match.js`(`joinTextItems`), `geometry.js` |
| `doc.js` | PDF 열기, 문서 지문, 쪽 그리기(보이는 쪽만), 배율, 쪽 이동 | pdf.js |
| `overlay.js` | 쪽마다 겹침층을 두고 형광펜·용어 밑줄·검색 결과·인용 영역을 그린다 | `geometry.js` |
| `selection.js` | 드래그한 범위를 쪽 글의 글자 범위로 바꾸고 선택 도구를 띄운다 | `text-map.js` |

| `search.js` | 본문 검색 | `text-map.js`, `overlay.js` |

| `panels.js` | 좌우 패널, 탭, 서랍 | 없음 |
| `reader.js` | 위 파일을 묶어 리더를 띄우고 키보드를 처리 | 전부 |

화면은 `reader.html`(개발 중 주소)과 `assets/reader/reader.css`다.

### 4.3 표시 위치 계산

이 리더의 중심 문제다. 2026-09-23 계획 문서에 적힌 대로, pdf.js 텍스트 레이어의 span 위에 표시를
얹는 시도는 세 번 철회됐다. span은 줄 단위로 만들어지고 폭을 CSS로 억지로 맞추기 때문에 그 안의
부분 문자열 위치가 실제 글자 위치와 어긋난다.

새 리더는 텍스트 레이어의 span 기하를 쓰지 않는다.

1. `page.getTextContent()`가 주는 글자 조각마다 위치 행렬, 폭, 글꼴 이름을 읽는다.
2. 조각 안의 글자별 가로 위치는 **PDF에 든 실제 글꼴로 측정**한다. pdf.js는 쪽을 그릴 때 내장
   글꼴을 `document.fonts`에 등록하므로, 캔버스 `measureText`에 그 글꼴 이름을 주면 글자별 폭을 얻는다.
   측정한 폭의 합을 조각의 실제 폭에 맞춰 비율로 보정한다.
3. 글꼴이 등록되지 않은 조각은 글자 종류별 가중치(한글·한자 1, 라틴 대문자 0.7, 소문자·숫자 0.55,
   공백 0.3)로 조각 폭을 나눈다.
4. 결과는 쪽 좌표계(배율 1)의 글자별 상자다. 배율이 바뀌어도 다시 계산하지 않고 곱하기만 한다.

선택(드래그)은 브라우저 선택 기능을 쓰기 위해 투명한 텍스트 레이어를 그대로 두되, 선택 범위를
읽을 때는 조각 번호와 조각 안 글자 위치만 가져오고 좌표는 위 상자에서 구한다.

이 방식이 실제 문서에서 맞는지는 작업 3에서 측정으로 확인한다(§7.1). 기준에 못 미치면 다음 순서로
물러난다.

- 조각(대개 한 줄) 안에서 글자 종류 가중치만으로 나눈 상자를 쓴다.
- 그래도 안 되면 표시 단위를 낱말 경계로 넓힌다(형광펜이 낱말 단위로 스냅).

어느 경우에도 텍스트 레이어 span 위에 표시를 감싸는 방식으로는 돌아가지 않는다.

### 4.4 데이터 흐름

1. `doc.js`가 파일을 열고 문서 지문을 만든다(지금의 `computeDocHash`와 같은 값). 이 지문으로
   저장된 형광펜·메모와 최근 문서를 찾는다.
2. 쪽이 화면에 들어오면 `doc.js`가 쪽을 그리고 `text-map.js`가 쪽 글과 글자 상자를 만든다. 쪽 글은
   옛 뷰어의 `joinTextItems` 결과와 같은 문자열이어야 한다(기존 기록의 글자 위치가 그대로 맞도록).
3. `terms-layer.js`, `annotations.js`, `search.js`, `refs.js`가 쪽 글에서 표시할 글자 범위를 구하고
   `overlay.js`가 그린다.
4. 드래그는 `selection.js`가 글자 범위로 바꿔 `annotations.js`에 넘긴다.
5. 문서 전체가 필요한 계산(참고문헌 목록, 목차 추정, 전체 용어 목록)은 문서를 연 뒤 쪽 글만 먼저
   뽑아 한가할 때 처리한다. 쪽을 그리는 일과 분리한다.

### 4.5 저장

형광펜·메모 한 건은 지금처럼 쪽 번호, 글자 위치(시작·끝), 인용한 글귀, 색, 메모로 저장한다.
Supabase 테이블 `tg_pdf_annotations`와 브라우저 저장소 키 `tg-pdf-annotations:<지문>`을 그대로 쓴다.

## 5. 읽기 보조의 판단 규칙

### 5.1 목차

1. `pdf.getOutline()`이 있으면 그것을 쓴다.
2. 없으면 제목을 추정한다. 본문 글자 크기(가장 많이 쓰인 크기)보다 크거나 굵은 글꼴이고, 한 줄이며,
   `1.`, `1.1`, `I.`, `제1장`, `Abstract`, `Introduction`, `References`, `서론`, `결론`, `참고문헌` 같은
   번호·표제 형식에 맞는 줄을 제목으로 본다.
3. 추정 결과가 3개 미만이면 목차가 없는 것으로 처리한다.

### 5.2 참고문헌과 인용

- 참고문헌 구역: `References`, `Bibliography`, `참고문헌`, `참고 문헌`, `인용문헌` 제목 줄 뒤부터 문서
  끝(또는 `Appendix`, `부록` 제목 전)까지.
- 항목 나누기: 줄 머리의 `[n]`, `n.`, `(n)` 번호. 번호가 없으면 내어쓰기와 "저자, (연도)" 형식으로 나눈다.
- 번호식 인용: `[12]`, `[3, 7]`, `[3–5]`와 위첨자 숫자. 번호가 참고문헌 항목 수 범위 안일 때만 연결.
- 저자-연도식 인용: `(Kim, 2020)`, `(Kim & Lee, 2020)`, `(Kim et al., 2020)`, `Kim et al. (2020)`,
  `(김철수, 2020)`, `(김철수 외, 2020)`. 첫 저자 성과 연도가 일치하는 항목이 **정확히 하나**일 때만 연결.
- 연결하지 못한 인용에는 카드를 띄우지 않는다.

### 5.3 그림·표·절·식 참조

- 대상: `Fig. 3`, `Figure 3`, `Table 2`, `Section 2.1`, `Sec. 2.1`, `Eq. (5)`, `Equation 5`,
  `그림 3`, `표 2`, `식 (5)`, `2.1절`.
- 대상 위치: 줄 머리에서 시작하는 같은 번호의 캡션(`Figure 3.`, `Fig. 3:`, `Table 2.`, `그림 3.`,
  `표 2.`), 절은 목차 항목, 식은 줄 오른쪽 끝의 `(5)`.
- 미리보기는 대상 위치를 포함한 쪽 영역을 잘라 보여 준다(그림은 캡션 위쪽, 표는 캡션 아래쪽으로
  쪽 높이의 40%).
- 대상을 찾지 못하면 미리보기를 띄우지 않는다.

### 5.4 외부 서지 조회

- "자세히"를 누를 때만 조회한다. 참고문헌 한 건의 서지 문구만 보낸다.
- Crossref REST API(`api.crossref.org/works?query.bibliographic=…&rows=3`)를 쓴다. 요청에 개인 식별
  정보를 넣지 않는다.
- 일치 판정: 결과 제목을 정규화(소문자, 기호 제거)한 낱말의 80% 이상이 서지 문구에 있고, 연도가
  서지 문구에 있는 연도와 같을 때만 보여 준다. 아니면 "일치하는 문헌을 찾지 못했습니다".
- 같은 문헌은 문서를 닫을 때까지 다시 조회하지 않는다.
- `privacy.html`에 "인용 카드에서 '자세히'를 누르면 해당 참고문헌의 서지 문구가 Crossref로
  전송된다"는 문장을 추가한다.

## 6. 예외 처리

| 상황 | 처리 |
|---|---|
| 글자 정보가 없는 PDF(스캔본) | 쪽은 보여 주고 "이 PDF는 글자를 인식할 수 없어 형광펜·용어 표시를 쓸 수 없습니다"를 한 번 안내. 쪽 이동·확대·쪽 축소 그림은 동작 |
| 일부 쪽만 글자가 없음 | 그 쪽만 표시 기능이 꺼짐 |
| 암호가 걸렸거나 깨진 파일 | 리더로 넘어가지 않고 첫 화면에 이유 표시 |
| 수백 쪽 문서 | 보이는 쪽 ±2만 그리고 멀어진 쪽은 캔버스를 비움 |
| 옛 형광펜·메모의 위치를 못 찾음 | 메모 패널에 "위치를 찾지 못함"으로 남김. 삭제하지 않음 |
| 드래그가 옆 단으로 번짐 | 선택 범위를 쪽 글의 읽기 순서로 정렬해 저장 |
| 목차를 만들 수 없음 | "이 문서에서는 목차를 찾지 못했습니다", "쪽" 탭을 기본으로 |
| 인용·참조의 대상을 못 찾음 | 카드·미리보기를 띄우지 않음 |
| 외부 서지 조회 실패 | 카드에 "정보를 가져오지 못했습니다"와 다시 시도. 논문 안의 서지 문구는 계속 표시 |
| 로그인 저장 실패 | 브라우저 저장소에 넣고 "메모가 이 기기에만 저장되었습니다" 안내 |
| 브라우저 저장소가 가득 참 | 저장 실패 안내. 화면의 표시는 닫을 때까지 유지 |

## 7. 검증

### 7.1 표시 위치(S1)

시험 논문 묶음: 한 단 국문, 두 단 국문, 한 단 영문, 두 단 영문, 목차 점선이 있는 문서, 자간이 큰
제목이 있는 문서, 스캔본. `docs/viewer-corpus/`와 `data/oa-corpus/`에서 고른다(이 폴더의 PDF는
커밋하지 않는다).

측정: 쪽마다 낱말을 무작위로 20개 골라 계산한 상자와 캔버스에 실제로 그려진 글자 영역(상자 안팎의
잉크 비율)을 비교한다. 상자 안에 그 낱말 잉크의 90% 이상이 들어가고, 상자의 가로 어긋남이 글자
높이의 25% 이하이면 맞은 것으로 본다. **맞은 비율 98% 이상**을 통과 기준으로 한다. 결과는
`scripts/reader-geometry-eval.js`가 표로 낸다.

### 7.2 인용 카드(S4)

시험 논문에서 카드가 뜬 인용을 문서마다 30건씩 확인해 맞는 문헌을 가리킨 비율을 잰다. **정밀도
98% 이상**이 기준이다. 못 미치는 인용 형식은 그 형식의 카드를 끈다. 재현율(연결된 인용의 비율)은
보고만 한다.

### 7.3 자동 테스트

`geometry.js`, `text-map.js`, `refs.js`, `outline.js`의 추정 부분, `biblio.js`의 일치 판정,
`annotations.js`의 다시 붙이기는 입력과 출력만으로 검증한다. 기존 테스트 245개는 그대로 통과해야 한다.

### 7.4 화면 확인

작업마다 브라우저에서 직접 열어 확인하고 화면 사진을 남긴다. 넓은 화면(1440px)과 좁은 화면(375px).
