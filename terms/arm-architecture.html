    ARM 아키텍처 (ARM Architecture)

    명령어 집합 구조›ARM 아키텍처
    컴퓨터과학·AI
    한 줄 정의: 전력 효율을 중시하는 명령어 집합(RISC 계열)에 기반해 설계된 프로세서 아키텍처로, 스마트폰과 최근에는 서버·노트북에도 널리 쓰인다.

    쉽게 풀면

    ARM은 CPU가 이해하는 명령어의 종류와 구조를 정의한 설계 방식으로, 인텔·AMD가 주로 쓰는 x86과는 다른 계열이다. 명령어를 단순하게 유지해서 전력을 적게 쓰면서도 효율적으로 동작하도록 설계되었기 때문에, 배터리로 움직이는 스마트폰과 태블릿의 표준이 되었다. 최근에는 애플 실리콘 맥이나 클라우드 서버에서도 ARM 기반 칩을 채택하면서 데스크톱·서버 영역까지 영향력을 넓히고 있다.

    왜 중요한가

    ARM 아키텍처는 저전력·고효율 컴퓨팅이라는 큰 흐름과 맞닿아 있어서, 온디바이스 AI·엣지 컴퓨팅·모바일 시스템을 다루는 논문에서 실험 환경을 설명할 때 자주 등장한다. 데이터센터용 서버 CPU 역시 ARM 기반 설계를 채택하는 사례가 늘면서, 전력 대비 성능(에너지 효율)을 다루는 컴퓨터 구조·시스템 연구에서도 비교 대상으로 언급된다. 또한 x86과 명령어 체계가 달라 소프트웨어 이식성·컴파일러 최적화·크로스 플랫폼 성능 평가 같은 주제와도 연결된다.

    핵심 정리

    ARM은 특정 칩의 이름이기 전에 명령어 집합 구조(ISA)의 계열이다(명령어 집합 구조). 소프트웨어가 CPU에 내리는 명령의 약속을 정한 것이어서, 같은 ISA를 따르는 서로 다른 회사의 칩이 같은 프로그램을 돌릴 수 있다.

    • 유래: “Acorn RISC Machine” 프로젝트가 1983년 10월에 시작되었고 첫 실리콘(ARM1)은 1985년에 동작을 확인했다. ARM이라는 이름은 이 프로젝트에서 왔다.
    • 사업 방식: Arm사는 ISA와 코어 설계를 라이선스로 제공한다. 코어 라이선스는 설계된 코어를 받아 칩을 만드는 것이고, 아키텍처 라이선스는 ISA를 따르면서 자기 코어를 직접 설계하는 것이다. 애플 M1의 코어처럼 자체 설계한 코어가 후자의 예이다.
    • 64비트: 2011년 ARMv8-A가 64비트 주소 공간과 64비트 연산을 도입했고, 이 64비트 실행 상태가 AArch64이다.

    낮은 비용, 적은 전력 소모와 발열 덕분에 스마트폰·태블릿·노트북과 임베디드 시스템에 널리 쓰이며, 2003년 이후 적어도 2,300억 개가 넘는 ARM 칩이 생산되어 가장 널리 쓰이는 ISA 계열이 되었다. 데스크톱과 서버에도 쓰여, 2020~2022년 세계에서 가장 빠른 슈퍼컴퓨터였던 일본의 후가쿠(Fugaku)도 ARM 기반이다.

    예시로 보기

    같은 소스 코드도 ISA마다 따로 컴파일해야 한다. 예를 들어 x86 컴퓨터에서 만든 실행 파일은 ARM 기반 보드에서 그대로 실행되지 않으므로, 교차 컴파일의 대상(target)을 aarch64처럼 지정하거나 ARM 기기에서 직접 빌드한다.

    논문이 실험 환경을 적을 때 ARM과 관련해 밝혀 두면 좋은 정보는 다음과 같다(형식 예시).

    • CPU 모델명과 ISA 버전(예: ARMv8-A), 코어 수와 클럭
    • 운영체제·컴파일러 버전과 최적화 옵션
    • 전력·에너지를 어떤 방법으로(외부 계측기, 내장 센서 등) 쟀는지
    • 비교 대상(x86 서버 등)의 사양, 그리고 같은 부하·같은 조건으로 비교했는지
    • 첫 ARM1은 내부 구조가 32비트였지만 주소 공간이 26비트여서 주기억장치가 64 MB로 제한되었다. ARMv3에서 32비트 주소 공간이 도입되었고 ARMv7까지 32비트가 이어졌다.
    • ARMv8-A(2011)는 64비트 주소 공간·연산과 함께 새로운 32비트 고정 길이 명령어 집합을 더했다.
    • Thumb 확장은 16비트·32비트 명령을 섞어 코드 밀도를 높이고, Jazelle은 자바 바이트코드를 직접 처리하는 명령을 더했다.

    ARM의 배경에는 Acorn Computers가 1981년 12월에 내놓은 BBC Micro가 있다. 6502 CPU를 썼지만 Hitachi에서 받은 빠른 4 MHz DRAM 덕분에 Apple II 같은 경쟁 기종보다 약 두 배 빨랐다.

    자주 하는 오해

    • “ARM은 Arm사가 만든 칩이다”: Arm사가 파는 것은 주로 설계(IP)와 ISA이고, 실리콘은 라이선스를 받은 회사들이 만든다.
    • “ARM이면 곧 저전력이다”: 전력과 성능은 ISA 이름만이 아니라 코어 설계(마이크로아키텍처), 제조 공정, 시스템 구성에 좌우된다. Blem 외(2013)는 ARM(RISC)과 x86(CISC)을 비교하며 “ISA 자체가 성능과 에너지 효율에 본질적 역할을 하는가”를 실제 하드웨어 측정으로 따져 본 연구이다.
    • “ARM은 휴대기기용이라 서버에는 못 쓴다”: 위 연구도 저전력이던 ARM이 고성능 서버 시장에, 고성능이던 x86이 모바일 시장에 진입하고 있다고 서술한다.

    예시 문장

    아래 예문은 용어의 쓰임을 보이려고 만든 것으로, 실제 논문 문장이 아니다.

    "엣지 디바이스 배포를 위해 모델을 ARM 기반 프로세서에서 양자화하여 실행하였다."

    스마트폰이나 임베디드 기기에 흔히 쓰이는 ARM 계열 프로세서에서 모델이 돌아가도록 경량화했다는 뜻이다.

    "제안한 스케줄링 기법을 ARM 기반 서버 클러스터에서 평가한 결과, 동일 작업량 대비 소비 전력이 기존 x86 환경보다 낮게 측정되었다."

    클라우드·서버 시스템 연구에서 ARM 서버 CPU를 사용해 에너지 효율을 비교 평가했다는 의미다.

    "바이너리 코드를 ARM 명령어 집합으로 교차 컴파일한 뒤, 실제 마이크로컨트롤러 보드에서 추론 지연 시간을 측정하였다."

    임베디드 시스템·펌웨어 분야에서 ARM용으로 코드를 변환해 실제 하드웨어 위에서 성능을 검증했다는 뜻이다.

    조금 더 깊게 보면

    ARM은 회사가 직접 칩을 만들지 않고 명령어 집합 구조(ISA)와 코어 설계를 라이선스로 제공하는 방식(IP 라이선싱)을 취하며, 이 때문에 퀄컴·애플·삼성 등 다양한 제조사가 저마다의 ARM 기반 칩을 만든다. 최근 세대의 ARM 아키텍처는 64비트 명령어 집합(AArch64 계열)을 중심으로 발전하고 있으며, 논문에서 성능을 비교할 때는 단순 실행 속도뿐 아니라 와트당 성능이나 코어별 전력 소비 같은 에너지 효율 지표를 함께 다루는 경우가 많다. 소프트웨어 측면에서는 x86용으로 작성된 코드를 ARM에서 실행하기 위한 교차 컴파일이나 에뮬레이션(예: 다른 아키텍처를 흉내 내어 실행하는 방식)이 자주 언급되는 주제다.

    주의할 점

    ARM은 인텔·AMD가 주로 쓰는 CISC 계열 명령어 체계와 근본적으로 달라, 한쪽에서 컴파일된 프로그램이 다른 쪽에서 그대로 실행되지 않는 경우가 많다.

    헷갈리기 쉬운 용어

    ISA, 코어 설계, 칩은 서로 다른 층이다.

    용어층예
    명령어 집합 구조(ISA)소프트웨어와 하드웨어 사이의 약속ARM, x86
    마이크로아키텍처ISA를 하드웨어로 구현한 코어 내부 설계같은 ARMv8-A를 구현한 서로 다른 회사의 코어
    SoC(시스템 온 칩)코어와 주변 회로를 묶어 제조한 제품스마트폰용 칩, 서버용 칩
    마이크로컨트롤러CPU·메모리·입출력을 한 칩에 담은 소형 제어용 칩ARM 코어를 쓰는 제품도 많음
