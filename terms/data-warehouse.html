    데이터 웨어하우스 (Data Warehouse)

    컴퓨터과학·AI
    한 줄 정의: 여러 시스템에서 수집된 대량의 정형 데이터를 통합·정제하여 분석과 보고에 최적화된 형태로 장기간 저장하는 중앙 집중형 데이터 저장소.

    쉽게 풀면

    데이터 웨어하우스는 회사나 조직의 여러 시스템에서 나온 데이터를 한곳에 모아 정리해 두는 대형 저장소이다. 매일 발생하는 실시간 거래 처리용 데이터베이스와 달리, 데이터 웨어하우스는 이미 정제된 과거 데이터를 오랫동안 쌓아두고 대규모 통계 분석이나 보고서 작성을 빠르게 할 수 있도록 최적화되어 있다. 연구에서는 여러 출처의 로그나 실험 결과를 통합 분석할 때 이런 데이터 웨어하우스를 구축해 활용하기도 한다.

    왜 중요한가

    여러 시스템에서 흩어져 생성되는 데이터를 각각 따로 분석하면 전체적인 추세나 시스템 간 관계를 파악하기 어렵다. 데이터 웨어하우스는 이런 데이터를 하나의 일관된 구조로 통합해 대규모 통계 분석과 장기 추세 파악을 가능하게 하므로, 경영정보시스템, 헬스케어 데이터 분석, 대규모 로그 분석을 다루는 논문에서 데이터 인프라를 설명할 때 자주 등장한다. 또한 데이터 웨어하우스를 어떻게 설계했는지는 이후 분석의 재현성과 확장성에도 직접적인 영향을 미친다.

    핵심 정리

    데이터 웨어하우스(DW, DWH)는 여러 원천에서 모은 데이터를 한곳에 통합해 두는 중앙 저장소이다. 엔터프라이즈 데이터 웨어하우스(EDW)라고도 부른다. 보고와 데이터 분석에 쓰이는 시스템이며 비즈니스 인텔리전스의 핵심 구성요소이다. 분석에 맞게 정리된 현재·과거 데이터를 저장하고, 분석가와 관리자가 의사결정에 쓴다.

    데이터의 네 가지 특성

    • 주제 지향성: 개별 업무 처리보다 판매, 환자 같은 분석 주제를 중심으로 데이터를 구성한다.
    • 통합성: 서로 다른 시스템에서 온 데이터를 하나의 일관된 형태로 맞춘다.
    • 시간 가변성: 운영 시스템과 달리 긴 기간(최대 약 10년)의 이력 데이터를 담는다.
    • 비휘발성: 적재된 데이터는 원칙적으로 갱신·삭제하지 않는 읽기 전용이다.

    구축 흐름

    데이터는 판매·마케팅 같은 운영 시스템에서 올라온다. 활용하기 전에 운영 데이터 저장소를 거치거나 데이터 정제를 받을 수 있다. 구축 방식은 크게 두 가지이다. ETL은 추출·변환·적재 순서로 진행하고, ELT는 추출·적재 후 웨어하우스 내부에서 변환한다.

    운영 DB와의 차이

    운영 데이터베이스(OLTP)와 데이터 웨어하우스(OLAP) 비교
    구분운영 DB (OLTP)데이터 웨어하우스 (OLAP)
    목적거래 기록, 무결성과 기록 속도대량 데이터를 읽어 관계와 추세 파악
    모델정규화, 개체-관계 모델다차원 스키마(주로 스타 스키마)
    질의짧고 잦은 거래거래량은 적고 집계가 많은 복잡한 질의
    데이터현재 상태 중심집계된 과거 이력 중심

    분석 처리를 거래용 데이터베이스와 분리하면 두 시스템의 성능이 모두 좋아진다. 웨어하우스는 ETL로 운영 시스템의 데이터를 주기적으로 옮겨 오면서 과거 이력을 유지한다.

    설계 방식

    차원 모델링에서는 거래 데이터를 수치형 사실과 문맥을 주는 차원으로 나눈다. 스타 스키마는 Ralph Kimball이, 3차 정규형(3NF) 방식은 Bill Inmon이 제시했다. OLAP의 기본 연산은 롤업, 드릴다운, 슬라이스 앤 다이스이다.

    개념의 역사

    1988년 IBM 연구자 Devlin과 Murphy가 '비즈니스 데이터 웨어하우스'라는 용어를 소개했다. 1992년 Inmon이 『Building the Data Warehouse』를, 1996년 Kimball이 『The Data Warehouse Toolkit』를 출간했다.

    예시로 보기

    소매 유통: 매장 판매 시스템, 온라인 주문 시스템, 마케팅 시스템이 각각 데이터를 쌓는다. 이를 웨어하우스에 모으면 판매액(사실)을 날짜·지역·상품(차원)별로 집계할 수 있다. 연도별 합계에서 월별 합계로 내려가는 것이 드릴다운이고, 반대로 올라가는 것이 롤업이다. 특정 지역이나 특정 기간만 잘라 보는 것이 슬라이스 앤 다이스이다.

    의료: 병원마다 전자의무기록, 검사정보시스템 등 형식이 다른 원천을 쓴다. 이를 통합해 임상·연구 분석에 쓸 때는 ICD-10, SNOMED CT 같은 코드 체계를 맞추는 것이 중요하다. HIPAA, GDPR 같은 개인정보 규제도 설계에서 고려한다.

    팀 단위 활용: 마케팅팀만 쓸 작은 분석 저장소를 따로 두는 경우가 있다. 이를 데이터 마트라 하며, 특정 팀이나 사업부를 위한 더 작고 집중된 웨어하우스이다.

    저장소 선택: 센서 원시 로그, 이미지, 텍스트처럼 형식이 제각각인 자료를 일단 쌓아 두려면 데이터 레이크가 맞다. 이미 정제된 정형 지표를 반복 집계하려면 웨어하우스가 맞다.

    자주 하는 오해

    • 운영 데이터베이스를 크게 만든 것이 웨어하우스라는 오해: 둘은 목적이 다르다. 운영 DB는 거래 기록 저장용이고, 웨어하우스는 대량 데이터를 읽어 관계와 추세를 파악하는 분석용이다.
    • 데이터 레이크와 같다는 오해: 데이터 레이크는 정형·반정형·비정형 데이터를 원시 형태로 모아 두고 필요할 때 처리한다. 웨어하우스는 정제·변환된 정형 데이터를 저장한다.
    • 비휘발성이라 데이터가 전혀 바뀌지 않는다는 오해: 적재된 데이터를 갱신·삭제하지 않는다는 뜻이다. 새로운 데이터는 주기적인 적재로 계속 추가되며, 이렇게 과거 이력이 쌓인다.
    • 구축은 반드시 ETL이라는 오해: 변환을 웨어하우스 안에서 수행하는 ELT 방식도 있다.
    • 설계 방식이 하나뿐이라는 오해: Kimball의 스타 스키마와 Inmon의 3NF 방식이 서로 다른 접근으로 제시되어 왔다. 논문에서는 어떤 방식을 썼는지 밝히는 것이 좋다.

    조금 더 깊게 보면

    데이터 웨어하우스는 흔히 여러 원천 시스템에서 데이터를 추출·변환·적재하는 ETL 과정을 거쳐 구축되며, 분석 목적에 맞게 사실(수치)과 차원(속성)을 구분해 저장하는 스타 스키마와 같은 구조가 널리 쓰인다. 실시간 거래를 빠르게 처리하는 데 최적화된 운영 데이터베이스(OLTP)와 달리, 데이터 웨어하우스는 대량의 데이터를 빠르게 집계·조회하는 분석 처리(OLAP)에 최적화되어 있다는 점이 핵심적인 차이이다. 최근에는 정형 데이터 중심의 데이터 웨어하우스와 비정형 데이터를 함께 다루는 데이터 레이크의 장점을 결합한 형태도 함께 논의된다.

    주의할 점

    데이터 웨어하우스는 정제된 정형 데이터를 다루는 데 최적화되어 있어, 원본 그대로의 비정형 데이터를 대량으로 쌓아두는 오브젝트 스토리지 기반의 데이터 레이크와는 목적이 다르다.
