    API (응용 프로그래밍 인터페이스)

    컴퓨터과학·AI
    한 줄 정의: 서로 다른 소프트웨어가 정해진 규칙에 따라 데이터나 기능을 주고받을 수 있게 해주는 약속된 통로입니다.

    쉽게 풀면

    식당에서 손님은 주방에 직접 들어가지 않고 메뉴판을 보고 종업원에게 주문합니다. 종업원은 정해진 방식으로 주문을 받아 주방에 전달하고, 완성된 음식을 다시 손님에게 가져다줍니다. API는 바로 이 "종업원"과 같습니다. 프로그램 A가 프로그램 B의 내부 코드를 몰라도, API가 정한 형식대로 요청을 보내면 B가 처리한 결과를 돌려받을 수 있습니다. 그래서 개발자들은 남이 만든 복잡한 기능을 처음부터 다시 만들지 않고도 API를 통해 빌려 쓸 수 있습니다.

    왜 중요한가

    API는 여러 시스템을 연결해 재사용 가능한 연구·서비스 파이프라인을 구성하는 기본 단위이기 때문에, 컴퓨터과학뿐 아니라 실험을 자동화하는 거의 모든 분야의 논문에서 다뤄집니다. 특히 대규모 언어 모델처럼 직접 학습·구동하기 어려운 자원을 API 호출만으로 활용할 수 있게 되면서, 연구 재현성과 비교 실험의 표준적인 방법론으로 자리 잡았습니다. 또한 여러 기관이 만든 데이터셋이나 도구를 API로 연결하는 방식은 대규모 협업 연구와 실무 시스템 통합 모두에서 핵심적인 역할을 합니다.

    논문에서는 이렇게 쓰입니다

    "본 연구에서는 OpenAI의 API를 통해 대규모 언어 모델을 호출하여 응답을 수집하였다."

    이 문장은 연구자가 모델을 직접 설치하지 않고, 정해진 요청 형식으로 서버에 데이터를 보내고 결과를 받아오는 방식으로 실험을 진행했다는 뜻입니다.

    "기상 관측소의 실시간 데이터는 공공데이터 API를 통해 수집되었으며, 결측값은 별도의 전처리 과정을 거쳐 보정하였다."

    생물·지구과학 분야 연구에서는 직접 측정 장비를 설치하는 대신, 정부나 기관이 제공하는 API를 통해 관측 데이터를 자동으로 받아오는 방식이 흔히 쓰입니다. 이 문장은 데이터 수집 단계에서 API가 반복적인 자료 확보를 자동화하는 통로로 사용되었음을 보여줍니다.

    "제안된 시스템은 결제사와 병원 정보시스템의 API를 연동하여 진료 데이터와 처방 정보를 실시간으로 교환하도록 설계되었다."

    의료 정보시스템 연구에서는 서로 다른 기관의 시스템이 데이터를 안전하게 주고받아야 하는데, 이때도 API가 그 연결 규칙 역할을 합니다. 이 예문은 API가 단순 데이터 조회를 넘어 서로 다른 조직 간 시스템 통합에도 쓰인다는 점을 보여줍니다.

    조금 더 깊게 보면

    논문에서 API를 언급할 때는 흔히 REST API 형식이 함께 등장하는데, 이는 HTTP 요청(GET, POST 등)을 이용해 자원을 주고받는 설계 방식을 뜻합니다. 최근에는 대규모 언어 모델 API처럼 요청 횟수나 처리량에 제한(rate limit)을 두는 경우가 많아, 실험 설계 시 이 제약을 고려했다는 언급이 방법론 절에 자주 등장합니다. 또한 API 응답의 일관성을 확인하기 위해 동일 요청을 여러 번 반복하거나, API 버전 변경으로 인한 결과 재현성 문제를 별도로 논의하는 연구도 있습니다.

    주의할 점

    API는 특정 프로그래밍 언어나 기술이 아니라 "규칙(인터페이스)" 자체를 가리키는 개념입니다. 웹에서 흔히 쓰이는 방식은 REST라는 설계 원칙을 따르는 경우가 많지만, API 자체는 그보다 훨씬 넓은 개념이며 버전 관리 시스템이나 운영체제 기능 호출에도 API라는 말이 쓰입니다.
