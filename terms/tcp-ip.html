    TCP/IP

    컴퓨터과학·AI

    ✓ 출처 대조 2026-11-08

    한 줄 정의: 인터넷에서 컴퓨터들이 데이터를 잘게 나누어 정확한 목적지까지 빠짐없이 전달할 수 있게 해 주는 통신 규칙(프로토콜) 묶음이다.

    쉽게 풀면

    큰 소포를 우체국에서 보낼 때, 내용물이 크면 여러 상자로 나누어 각 상자에 순서 번호와 받는 사람 주소를 적어 보내는 것을 떠올려 보자. TCP/IP도 비슷하게 동작한다. IP(Internet Protocol)는 "받는 사람 주소"를 붙여 각 데이터 조각(패킷)이 어디로 가야 하는지 알려주고, TCP(Transmission Control Protocol)는 "상자에 번호를 매기고 다 도착했는지 확인"하는 역할을 한다. 중간에 조각 하나가 사라지거나 순서가 뒤바뀌어도, TCP가 다시 요청하거나 순서를 맞춰서 원래 데이터를 완벽하게 복원해 준다.

    왜 중요한가

    TCP/IP는 오늘날 거의 모든 인터넷 통신의 기반이 되는 표준이기 때문에, 새로운 네트워크 프로토콜이나 분산시스템을 제안하는 논문은 기존 TCP/IP 스택과의 호환성이나 그 위에서의 성능을 반드시 검증해야 한다. 클라우드 컴퓨팅, IoT, 5G 네트워크, 보안 연구 등 통신이 관여하는 거의 모든 컴퓨터과학 분야에서 실험 환경의 기본 전제로 다뤄지는 개념이다.

    핵심 정리

    • TCP/IP, 곧 인터넷 프로토콜 모음은 미국 국방부 고등연구계획국(DARPA)이 지원한 ARPANET 연구에서 나왔다. 서프와 칸이 1974년 5월 인터네트워킹 설계를 발표했고, 같은 해 12월 첫 TCP 명세(RFC 675)가 나왔다. 1978년 포스텔이 TCP와 IP(버전 4)로 나누었다. 미국 국방부는 1982년 3월 TCP/IP를 군 표준으로 선언했고, ARPANET은 1983년 1월 1일 NCP에서 TCP/IP로 전환했다.
    • 네 계층: RFC 1122·1123은 링크, 인터넷, 전송, 응용의 네 계층을 정의한다. RFC는 계층에 번호를 붙이지 않고 이름만 부른다. 응용 데이터는 계층을 내려갈 때마다 해당 계층의 프로토콜 단위로 감싸지는데, 이를 캡슐화라 한다.
    • RFC 1122는 링크 계층은 직접 연결된 네트워크와의 접속, 인터넷 계층은 IP로 출발지에서 목적지까지 데이터를 나르는 비연결형 데이터그램 서비스(ICMP·IGMP 포함), 전송 계층은 응용에 종단 간 통신 서비스를 제공하는 TCP·UDP, 응용 계층은 Telnet·FTP·SMTP 같은 최상위 계층이라고 서술한다.
    • TCP는 연결 지향 프로토콜로, 데이터를 순서대로 전달하고 오류를 줄이며 중복을 버리고 손실된 패킷을 다시 보내고 혼잡을 제어한다.
    • IP는 네트워크를 가로지르는 최선형(best-effort), 비신뢰성 데이터그램 전달을 맡는다. IPv4는 32비트 주소로 약 40억 호스트를 구분하고, 1998년 표준화된 IPv6는 128비트 주소를 쓴다.
    • UDP는 비연결형 최선형 프로토콜이며 체크섬으로 오류를 감지한다. 스트리밍 미디어와 DNS 조회 같은 단순한 질의에 맞는다.

    예시로 보기

    • 소포 비유: 큰 데이터를 여러 조각(패킷)으로 나누어 각각에 목적지 주소(IP)를 붙이고, TCP가 순서와 재전송을 챙긴다고 생각하면 된다. 이 비유는 이해를 돕기 위한 것이다.
    • OSI 모델과의 비교: TCP/IP 모델에는 세션·프레젠테이션 계층이 따로 없고, 응용 계층이 OSI의 5~7계층에 대략 해당한다. TCP/IP는 OSI 모델보다 먼저 나왔다. IETF의 RFC 3439에는 “Layering Considered Harmful”이라는 절이 있다.
    • 논문에서: 새 프로토콜이 TCP/IP 스택 위에서 동작하는지, 무선 센서망처럼 손실률이 높은 환경에서 TCP의 혼잡 제어가 성능을 떨어뜨리는지를 다룬다.

    자주 하는 오해

    • “TCP/IP는 하나의 프로토콜이다”: TCP와 IP를 비롯한 여러 프로토콜의 모음이다. 1978년에 TCP와 IP로 나뉘었다.
    • “IP도 데이터가 도착하는 것을 보장한다”: IP는 최선형 전달만 한다. 순서와 재전송은 TCP의 몫이다.
    • “TCP/IP는 OSI 7계층과 같다”: TCP/IP는 네 계층이며 세션·프레젠테이션 계층이 따로 없다.
    • “UDP는 쓸모없는 프로토콜이다”: 스트리밍과 DNS 조회처럼 빠른 단순 질의에 쓰인다.

    조금 더 깊게 보면

    TCP/IP는 흔히 응용 계층, 전송 계층, 인터넷 계층, 네트워크 접근 계층으로 나뉘는 계층 구조로 설명되며, 각 계층은 자신의 역할만 처리하고 아래위 계층과는 정해진 규칙으로만 데이터를 주고받는다. TCP는 데이터를 순서대로 빠짐없이 전달하는 신뢰성을 보장하는 대신 속도가 상대적으로 느린데, 실시간 스트리밍처럼 신뢰성보다 속도가 중요한 경우에는 신뢰성을 포기하는 대신 더 빠른 UDP가 대안으로 쓰인다. 논문에서 통신 프로토콜을 평가할 때는 어떤 계층에서, 어떤 지표(지연시간, 처리량, 패킷 손실률 등)로 성능을 측정했는지 확인하는 것이 중요하다.

    주의할 점

    TCP/IP는 도메인 이름이 아니라 숫자로 된 IP 주소로 통신한다. 사람이 입력한 도메인 이름(예: example.com)을 IP 주소로 바꿔주는 과정은 도메인 네임 시스템(DNS)이 미리 처리해 준 뒤에야 TCP/IP 통신이 시작된다.
