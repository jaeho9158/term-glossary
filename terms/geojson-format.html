    GeoJSON 형식 (GeoJSON Format)

    지도학
    한 줄 정의: JSON 문법을 이용해 점, 선, 면 등의 지리 도형과 속성 정보를 표현하는 텍스트 기반 공간자료 형식이다.

    쉽게 풀면

    GeoJSON은 지도 도형을 웹에서 흔히 쓰는 JSON이라는 텍스트 형식으로 표현한 것이다. 메모장으로도 열어서 내용을 확인할 수 있을 만큼 구조가 단순하고 사람이 읽기에도 어렵지 않다. 웹 지도 서비스와 프로그래밍 언어 대부분이 JSON을 기본으로 다루기 때문에, GeoJSON은 웹에서 지도 데이터를 주고받을 때 특히 편리하다. 하나의 파일 안에 여러 도형과 속성을 함께 담을 수 있다는 점도 특징이다.

    왜 중요한가

    웹 기반 지도 서비스와 오픈소스 GIS 생태계가 확산되면서 브라우저에서 바로 읽고 렌더링할 수 있는 GeoJSON의 활용도가 크게 늘었다. 연구자들도 분석 결과를 웹 지도나 대화형 시각화로 공유할 때 자주 사용하며, 데이터 공유의 개방성과 재현성을 높이는 형식으로 다뤄진다.

    핵심 정리

    • GeoJSON은 JSON을 바탕으로 단순한 지리 객체와 그 비공간 속성을 표현하는 개방형 표준 형식이다.
    • 도형 유형은 점(Point), 선(LineString), 면(Polygon)과 이들의 다중 도형(MultiPoint, MultiLineString, MultiPolygon), GeometryCollection이다.
    • Feature 객체는 도형과 속성(properties)을 갖고, 여러 Feature를 FeatureCollection으로 묶는다.
    • 좌표는 [x, y] 또는 [x, y, z]로 쓰며, 모두 WGS 84 측지계의 십진 각도 단위이다. 런던은 [-0.1278, 51.5074]처럼 경도, 위도 순서다.

    예시로 보기

    표준화 경과는 다음과 같다. 2007년 3월 작업 그룹이 시작되어 2008년 6월 명세가 확정되었고, 2015년 4월 IETF가 Geographic JSON 작업 그룹을 만들어 2016년 8월 RFC 7946으로 발표했다.

    관련 형식으로 위상을 담아 보통 파일이 더 작은 TopoJSON, 한 줄에 한 객체를 담는 GeoJSONSeq와 GeoJSONL이 있다. 다른 공간자료 형식은 셰이프파일과 비교할 수 있고, 웹 지도 좌표는 웹 메르카토르와 연결된다.

    자주 하는 오해

    • 좌표 순서가 위도, 경도라는 오해: GeoJSON은 경도, 위도 순서이다.
    • 다른 좌표계를 지정할 수 있다는 오해: RFC 7946 이후 WGS 84를 전제한다. 이전 판에서 쓰던 좌표계 지정 방식은 쓰지 않는다.
    • 복잡한 위상 분석에 적합하다는 오해: 단순 지리 객체 표현용이며, 위상을 담으려면 TopoJSON 등을 쓴다.

    예시 문장

    아래 예문은 용어의 쓰임을 보이려고 만든 것으로, 실제 논문 문장이 아니다.

    "수집된 관측 지점 좌표를 GeoJSON(GeoJSON) 형식으로 정리하여 웹 기반 시각화 도구에 입력하였다."

    현장에서 얻은 좌표 자료를 웹에서 바로 표시할 수 있도록 GeoJSON으로 변환했다는 의미이다.

    "공개된 행정경계 GeoJSON 파일을 활용하여 지역 단위 통계지도를 제작하였다."

    이미 배포된 GeoJSON 경계 자료를 불러와 통계지도의 바탕 도형으로 사용했다는 뜻이다.

    조금 더 깊게 보면

    GeoJSON은 점(Point), 선(LineString), 면(Polygon) 및 이들의 복합 형태를 하나의 표준 문법으로 표현하며, 좌표는 일반적으로 위경도(WGS84) 기준으로 기록된다. 속성 정보는 도형과 함께 key-value 쌍으로 저장되어 별도의 테이블 파일 없이도 자료를 한 파일에 담을 수 있다. GeoJSON은 사람이 읽을 수 있는 텍스트 기반 형식이라 별도 프로그램 없이도 내용을 확인할 수 있고, 웹 개발에서 흔히 쓰이는 데이터 형식과 문법이 같아 웹지도 서비스에 손쉽게 연동된다.

    주의할 점

    텍스트 기반이라 대용량 자료에서는 파일 크기가 커지고 처리 속도가 느려질 수 있어, 방대한 자료에는 다른 형식이 더 적합할 수 있다. 좌표계 표기가 명시되지 않은 경우 다른 좌표계 자료와 혼동할 위험도 있다. GeoJSON은 좌표계를 위경도(WGS84)로 가정하는 것이 관례이므로, 다른 좌표계의 자료를 변환 없이 그대로 저장하면 위치가 어긋날 수 있다.

    참고 문헌

    1. Butler, H., Daly, M., Doyle, A., Gillies, S., Hagen, S., & Schaub, T. (2016). The GeoJSON Format. RFC 7946. IETF.
    2. Wikipedia contributors. (n.d.). GeoJSON. Wikipedia.
