# PDF 뷰어 개선 계획 (2026-09-23)

## 0. 문제 정의

뷰어의 약속은 "논문 PDF를 올리면 **읽는 자리에서** 모르는 용어의 뜻을 바로 본다"이다.
지금 PDF 모드는 이 약속을 못 지킨다. 용어는 오른쪽 패널에 목록으로만 뜨고, 본문 위에는
아무 표시도 없다. 표시를 붙이려는 시도(텍스트 레이어 밑줄·팝오버, 더블클릭 모달, 주제
기반 숨김)는 세 번 모두 철회됐다.

철회 사유를 보면 원인은 하나로 모인다. **pdf.js 텍스트 레이어의 span 기하(위치·폭)를 신뢰
할 수 없는데, 그 위에 표시를 얹으려 했다.** span은 줄 단위로 생성되고 폭을 CSS scaleX로
억지로 맞추기 때문에, 그 안의 부분 문자열 위치는 실제 글자 위치와 어긋난다. 목차 점선 행,
2단 조판, 자간이 큰 제목에서 특히 심하다. 이 접근을 네 번째로 반복하면 같은 결과가 나온다.

두 번째 축은 매칭 품질이다. 3.7만 표제어 사전을 단순 문자열 일치로 돌리면 "강도", "배경"
같은 일상어 오탐이 나고, 지금은 손으로 만든 약 60개 블록리스트(`viewer.js:85-108`)로 막는다.
fuzzy 매칭은 오탐 때문에 꺼져 있고, 주제 기반 숨김은 철회됐다.

## 1. 목표와 성공 기준

| # | 목표 | 성공 기준(검증 가능) |
|---|---|---|
| G1 | 본문 안에서 용어 표시·뜻 보기 | 테스트 말뭉치 10편에서 표시 위치 오류 0건, 클릭→뜻 팝오버 100% |
| G2 | 오탐 줄이기 | 말뭉치 10편 기준 오탐률 ≤ 5%(수동 채점), 놓친 전문용어(미탐) ≤ 10% |
| G3 | 읽기 흐름 유지 | 페이지 이동·줌 후에도 표시/메모 유지, 첫 화면까지 ≤ 3초(30쪽 PDF, 일반 노트북) |
| G4 | 모바일에서 쓸 수 있음 | 375px 폭에서 본문 읽기·용어 뜻 보기·메모가 가능 |
| G5 | 실패가 보임 | 저장 실패·스캔본·텍스트 없음 등은 사용자에게 문구로 안내(무음 실패 0) |

**테스트 말뭉치**: 한국어 논문 PDF 10편을 `docs/viewer-corpus/`(비공개, .gitignore)에 둔다.
구성 — 단일단 5, 2단 3, 목차·점선 포함 1, 스캔본(텍스트 없음) 1. 각 편에 "정답 용어 목록"을
사람이 한 번 만들어 두고, 이후 모든 변경은 이 말뭉치로 채점한다. 이게 없어서 지금까지
"실제 문서에서 또 어긋남"이 반복됐다.

## 2. 핵심 결정: 렌더링 전략

### 안 A — 읽기 모드(reflow) 기본 + 원본(canvas) 토글  ← **권장**
- 페이지별 추출 텍스트를 HTML 문단으로 다시 흘려서 보여준다. 텍스트 모드가 이미 이 방식이고
  안정적이다(`renderRenderedPane`).
- 용어 밑줄·팝오파·검색·메모를 전부 **텍스트 오프셋**에 앵커한다. 픽셀 좌표를 쓰지 않으므로
  줌·재렌더·모바일에 영향받지 않는다.
- 원본 레이아웃(그림·표·수식)이 필요하면 "원본 보기" 토글로 canvas를 같은 페이지 위치에 띄운다.
- 비용: 2단 조판의 문단 순서 복원(`joinTextItems` 보강), 그림·표는 읽기 모드에서 빠짐(원본 토글로 보완).

### 안 B — 텍스트 레이어 위 표시 재도전
- pdf.js 자체 검색 하이라이트와 같은 방식(span 안에 mark 삽입). 이미 `runPdfSearch`가 이렇게
  동작한다.
- 장점: 원본 레이아웃 그대로. 단점: 철회된 바로 그 문제(span 폭 왜곡)가 그대로 남는다. 글자
  단위 위치를 얻으려면 `getTextContent` item의 transform으로 직접 박스를 계산해야 하고,
  이는 사실상 pdf.js 텍스트 레이어를 다시 만드는 일이다.

### 결정
**A를 기본으로 간다.** B는 1단계 스파이크에서 말뭉치 10편으로 위치 오류를 재어 보고, 오류가
0이면 "원본 보기" 상태에서만 보조 표시로 붙인다. 오류가 하나라도 있으면 B는 접는다.

## 3. 단계

### 1단계 — 말뭉치·측정 (½일)
1. 말뭉치 10편 + 정답 용어 목록 작성.
2. `scripts/viewer-eval.js`: 말뭉치를 돌려 오탐/미탐/표시 오류를 표로 출력. 이후 모든 단계의
   완료 조건은 이 스크립트 결과다.
3. 안 B 스파이크: 현 `runPdfSearch` 경로에 용어 mark를 얹고 10편에서 위치 오류를 센다. 결과로
   B 채택 여부 확정.

### 2단계 — 읽기 모드 (2일)
1. PDF 모드에서 페이지별 텍스트를 `<section data-page=N>`으로 흘리는 `renderReadingPane`.
   2단 조판은 `getTextContent` item의 x 좌표로 열을 나눈 뒤 열 순서로 잇는다(`joinTextItems` 확장,
   단위 테스트 추가).
2. 텍스트 모드의 밑줄·팝오버 코드를 그대로 재사용한다(오프셋 앵커).
3. "원본 보기" 토글: 같은 페이지의 canvas를 읽기 모드 옆/아래에 표시. 기존 지연 렌더·줌 코드 유지.
4. 검색은 읽기 모드 DOM에서 수행(현 `runPdfSearch`를 텍스트 레이어 대신 읽기 DOM으로).
5. 완료: 말뭉치 10편 표시 오류 0, 스캔본은 안내 문구.

### 3단계 — 매칭 품질 (1½일)
1. 손 블록리스트를 **데이터 기반 점수**로 교체: 표제어마다 (a) 일반어 여부 — 국립국어원
   빈도 목록 상위권이면 감점, (b) 사전 내 정의문 말뭉치에서의 문서빈도, (c) 길이(1–2음절 감점).
   점수는 빌드 시 `viewer-index.json`에 1바이트로 넣는다. 런타임 비용 없음.
2. 문서 분야 추정을 **숨김이 아니라 정렬**에 쓴다: 문서에서 잡힌 용어들의 분야 분포로 상위
   분야 2–3개를 추정하고, 그 분야 용어를 패널 위로 올린다. 나머지는 접힌 "다른 분야" 아래.
   (철회된 a4cdbf8d6은 숨겨서 문제였다. 정렬은 잃는 게 없다.)
3. 같은 용어가 문서에 여러 번 나오면 첫 등장에만 밑줄, 이후는 얇게(소음 감소).
4. **포함 관계 처리**(사례: '응력'이 '전단응력'보다 위에 뜸). 잡힌 용어끼리 표제어 포함 관계가
   있으면 긴 용어를 대표로 위에 두고 짧은 용어는 그 아래 "기초 용어"로 접는다. 본문 밑줄은 긴
   일치 우선 — '전단응력' 자리에 '응력'을 따로 긋지 않는다. '응력' 단독 등장은 그대로 잡는다.
5. 완료: 말뭉치 오탐 ≤ 5%, 미탐 ≤ 10%. 블록리스트 상수 삭제.

### 4단계 — 읽기 UX (1일)
1. 패널을 현재 페이지에 동기화: 스크롤 위치의 페이지 용어가 맨 위, 나머지는 페이지 번호로 그룹.
2. 팝오버: 정의 + "이 페이지에서 N번" + 용어 페이지 링크. 모바일(≤400px)은 바닥 시트.
3. 업로드 진입: 첫 화면에서 드래그앤드롭 영역 + 버튼을 같은 크기로 나란히(이번에 버튼 스타일
   추가한 것의 연장).
4. 완료: 375px에서 G4 시나리오 수동 통과.

### 5단계 — 저장·오류 (½일)
1. 메모·하이라이트를 텍스트 오프셋+페이지로 저장(기존 픽셀/range 저장분은 1회 마이그레이션).
2. 최근 문서 1개 → 5개(IndexedDB), 용량 초과 시 오래된 것부터 정리하고 문구로 알림.
3. 무음 `catch` 전수 점검: 사용자에게 영향이 있는 실패는 `#pdf-status`로 표시.

### 6단계 — 정리 (½일)
- Fuse.js 로드 제거(미사용), 매직넘버 상수 모음으로 이동, `wrapPageRange` 오프셋 순서 불변식에
  런타임 검증 추가, 테스트 보강(`joinTextItems` 2단, 점수 계산, 오프셋 앵커 복원).

총 6일 안팎. 단계마다 커밋하고 1·2단계가 끝나면 배포해 실제 반응을 본다.

## 4. 하지 않을 것
- 텍스트 레이어 픽셀 위치에 의존하는 표시(네 번째 재시도 금지, 1단계 스파이크가 0 오류일 때만 예외).
- 번역(비용·품질 문제로 이미 제거).
- fuzzy 매칭 재활성화(말뭉치로 오탐 ≤ 5%를 먼저 달성한 뒤에만 검토).

## 5. 열린 질문(결정 필요)
1. 안 A 채택 여부 — 원본 레이아웃을 기본으로 보여야 한다면 계획이 달라진다.
2. 말뭉치용 논문 10편은 누가 고르는가(저작권상 비공개 로컬 보관).
3. 3단계의 일반어 빈도 목록 출처(국립국어원 공개 자료 사용 가능 여부).

### 아직 검증되지 않은 것

성공 기준(1절)을 실제로 잰 적이 없는 항목이다. 다음에 손대는 사람이 여기부터 본다.

- **실제 한국어 논문 PDF 말뭉치 10편을 확보하지 못했다.** `docs/viewer-corpus/`에는 합성 샘플만
  있고, G1(표시 오류 0)·G2(오탐 ≤ 5%, 미탐 ≤ 10%)는 그 샘플로만 0이다. 1절의 수치 목표는
  아직 "달성"이 아니라 "측정 전"으로 읽어야 한다.
- **안 B 스파이크(1단계 3번)를 실행하지 않았다.** 텍스트 레이어 위 표시의 위치 오류를 재지
  않은 채 안 A로 갔다. 2절의 결정(오류 0이면 보조 표시로 붙인다)은 그대로 열려 있다.
- **2단 조판 판정 임계값(`COLUMN_*` 4개)은 합성 PDF로만 맞췄다.** 실제 2단 논문에서 단일단을
  2단으로 오인하거나 그 반대가 나는지는 확인되지 않았다.
- **표준 14폰트(비임베드) PDF의 캔버스 렌더를 확인하지 않았다.** 읽기 모드는 텍스트만 쓰므로
  영향이 없지만, "원본 보기"에서 글자가 빠지거나 다른 폰트로 대체될 수 있다.
- **Supabase 경로를 실측하지 못했다.** 로그인 세션이 없어 하이라이트·메모·읽은 기록은 로컬
  (IndexedDB/localStorage) 경로만 실제로 돌려 봤다.
- **페이지 경계를 넘는 일치는 읽기 모드에서 밑줄을 생략한다**(`splitMatchesByPage`). 페이지가
  각각 다른 `<section>`이라 감쌀 자리가 없어서다. 드물지만 0은 아니고, 패널 목록에는 나온다.
