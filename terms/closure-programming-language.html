    클로저 (closure)

    컴퓨터과학·AI
    한 줄 정의: 함수가 정의될 당시의 어휘적 환경(주변 변수들)을 함께 포획하여, 그 함수가 나중에 다른 곳에서 호출되더라도 정의 시점의 변수들에 계속 접근할 수 있게 하는 프로그래밍 언어의 기능.

    쉽게 풀면

    클로저는 함수가 태어난 곳의 '기억'을 가지고 다니는 것과 같다. 어떤 함수 안에서 또 다른 함수를 만들어 반환하면, 그 안쪽 함수는 바깥 함수의 지역 변수들을 마치 배낭에 담아가듯 함께 가지고 나간다. 그래서 바깥 함수의 실행이 이미 끝난 뒤에도, 반환된 안쪽 함수는 여전히 그 변수들에 접근하고 값을 바꿀 수 있다. 이 기능은 카운터를 만들거나 콜백 함수에 상태를 담아 전달하는 등 함수형 프로그래밍과 이벤트 기반 프로그래밍에서 매우 널리 활용된다.

    왜 중요한가

    클로저는 함수를 값으로 다루는 함수형 프로그래밍의 핵심 토대이며, 상태를 캡슐화하면서도 전역 변수를 늘리지 않고 코드를 모듈화할 수 있게 해준다. 그래서 프로그래밍 언어 설계, 정적 분석, 컴파일러 최적화 분야의 논문에서 함수의 어휘적 스코프와 실행 환경을 다룰 때 빠지지 않고 등장한다. 또한 비동기 프로그래밍, 이벤트 기반 아키텍처, 고차 함수 기반 API 설계에 관한 소프트웨어공학 연구에서도 클로저가 상태를 어떻게 유지·전파하는지가 중요한 분석 대상이 된다.

    논문에서는 이렇게 쓰입니다

    "본 이벤트 핸들러는 클로저를 이용해 등록 시점의 지역 변수를 캡처함으로써, 콜백이 나중에 호출되더라도 해당 컨텍스트에 접근할 수 있도록 하였다."

    함수가 자신이 정의된 환경의 변수를 계속 참조하는 프로그래밍 언어 기능을 설명할 때 사용된다.

    "제안하는 정적 분석 기법은 클로저가 포획한 자유 변수를 추적하여, 함수 호출 시점이 아닌 정의 시점의 스코프를 기준으로 데이터 흐름을 계산한다."

    프로그램 분석·컴파일러 연구에서 클로저의 자유 변수 포획이 데이터 흐름 분석의 대상이 됨을 설명할 때 쓰인다.

    "실험에 사용한 서버리스 함수들은 클로저를 통해 이전 호출의 캐시 상태를 유지하도록 구현되었으며, 이는 콜드 스타트 이후에도 일부 상태 정보를 재사용할 수 있게 하였다."

    분산 시스템·서버리스 컴퓨팅 연구에서 클로저를 이용해 함수 인스턴스 간 상태를 유지하는 구현 방식을 설명할 때 사용된다.

    조금 더 깊게 보면

    클로저를 논문에서 정확히 이해하려면 '자유 변수(free variable)'와 '어휘적 스코프(lexical scope)' 개념을 함께 봐야 한다. 클로저는 함수 본문에서 자신이 직접 선언하지 않은 변수, 즉 자유 변수를 감싸는 환경(environment) 구조체와 함께 표현되는데, 이 환경이 실제로 어떻게 표현되고 저장되는지는 언어 구현체마다 다르다. 일부 언어는 캡처된 변수를 값으로 복사하고(값에 의한 캡처), 다른 언어는 변수 자체에 대한 참조를 유지한다(참조에 의한 캡처)는 차이가 있으며, 이 차이는 반복문 안에서 클로저를 여러 개 생성할 때 관찰되는 동작 차이의 원인으로 자주 논의된다. 정적 분석·컴파일러 관련 논문에서는 이러한 캡처 방식이 코드 최적화, 탈출 분석(escape analysis), 메모리 관리 전략과 어떻게 상호작용하는지를 다루는 경우가 많다.

    주의할 점

    클로저가 외부 변수를 계속 참조하고 있으면 그 변수가 담긴 메모리가 가비지 컬렉터에 의해 회수되지 않고 계속 유지되므로, 의도치 않은 메모리 누수의 원인이 될 수 있다.
