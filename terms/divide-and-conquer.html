    분할정복 (Divide and Conquer)

    알고리즘의 개념›분할정복
    컴퓨터과학·AI
    한 줄 정의: 큰 문제를 풀기 쉬운 작은 문제들로 쪼갠 뒤, 각각을 따로 해결하고 그 결과를 합쳐서 원래 문제의 답을 구하는 방법이다.

    쉽게 풀면

    두꺼운 전화번호부에서 특정 이름을 찾는 상황을 떠올려보자. 첫 페이지부터 한 장씩 넘기며 찾으면 오래 걸리지만, 책을 절반으로 쪼개 찾는 이름이 앞쪽에 있는지 뒤쪽에 있는지 판단한 뒤, 해당하는 절반만 다시 절반으로 쪼개는 식으로 반복하면 훨씬 빨리 찾을 수 있다.

    이렇게 큰 덩어리를 계속 절반(혹은 여러 조각)으로 나누어 각각을 간단히 해결한 다음, 그 답들을 다시 조립해서 전체 답을 만드는 전략이 분할정복이다. "나누기(Divide) → 각자 풀기(Conquer) → 합치기(Combine)"의 세 단계로 요약된다.

    왜 중요한가

    분할정복은 정렬, 탐색, 행렬 연산 등 컴퓨터과학의 기초 알고리즘 설계 패러다임 중 하나로, 문제의 규모가 커질수록 계산량이 얼마나 늘어나는지를 분석하는 알고리즘 복잡도 이론과 밀접하게 연결된다. 또한 부분 문제들이 서로 독립적이라는 특성 덕분에 병렬·분산 컴퓨팅 환경에 자연스럽게 적용할 수 있어, 대규모 데이터를 다루는 시스템 논문에서 성능 개선 전략으로 자주 인용된다.

    어떤 절차인가

    1. 분할: 문제를 같은 종류의 더 작은 문제 a개로 나눈다(각 크기 약 n/b).
    2. 정복: 부분 문제를 재귀로 푼다. 충분히 작아지면(기저 사례) 직접 푼다.
    3. 결합: 부분 문제의 답을 합쳐 원래 문제의 답을 만든다.

    실행 시간은 점화식 T(n) = a·T(n/b) + f(n)으로 쓴다. f(n)은 나누고 합치는 비용이다. 이 형태의 점화식은 마스터 정리로 푼다. 병합 정렬은 T(n) = 2T(n/2) + Θ(n)이어서 Θ(n log n), 이진 탐색은 T(n) = T(n/2) + Θ(1)이어서 Θ(log n)이다.

    역사적으로 이진 탐색을 컴퓨터용으로 분명히 서술한 것은 John Mauchly의 1946년 글이다. 병합 정렬은 1945년 John von Neumann이 만들었다. Gauss는 1805년에 지금의 쿨리-튜키 FFT에 해당하는 방법을 서술했으나 연산 횟수를 분석하지 않았고, 한 세기 넘게 지나 재발견된 뒤에 널리 쓰이게 되었다. 1960년 Anatolii Karatsuba는 n자리 두 수의 곱셈을 O(nlog₂3) 연산에 하는 방법을 내, 곱셈에 Ω(n²) 연산이 필요하다는 Kolmogorov의 1956년 추측을 반증했다.

    언제 쓰고 무엇을 얻나

    정렬, 탐색, 행렬 곱셈, 고속 푸리에 변환처럼 문제를 독립적인 부분으로 나눌 수 있을 때 쓴다.

    가상의 예(실험) 같은 난수 배열에서 병합 정렬(분할정복)과 삽입 정렬이 수행한 비교 횟수를 센 결과이다(시드 고정).

    입력 크기 n병합 정렬삽입 정렬n·log₂n
    1005432,234664
    1,0008,702251,4599,966
    10,000120,49524,788,345132,877

    n이 100배 커질 때 병합 정렬의 비교 횟수는 약 220배, 삽입 정렬은 약 1만 1천 배가 된다. n·log₂n은 병합 정렬 횟수의 상한 근처에 있는 값이다.

    부분 문제가 서로 겹치면 같은 계산을 반복하므로 동적계획법이 낫는다. 나누고 합치는 비용이 크면 분할이 이득이 되지 않을 수도 있고, 항상 탐욕 알고리즘보다 빠른 것도 아니다.

    역사적으로 von Neumann이 1945년에 고안한 병합 정렬이 컴퓨터용 분할정복 알고리즘의 초기 예이다. 부분 문제가 하나뿐인 이진 탐색이나 유클리드 호제법은 따로 ‘감소정복’이라 부르자는 제안도 있다.

    부분 문제들은 서로 독립이라 여러 프로세서에 나눠 병렬로 풀기 좋다. 또 문제가 충분히 작아지면 캐시에 들어가므로, 캐시 크기를 몰라도 캐시를 잘 쓰는 알고리즘(캐시 무관 알고리즘)을 만들 수 있다.

    기저 사례를 비교적 크게 잡아 그 이하에서는 재귀 없이 풀면 효율이 좋아지는 하이브리드 알고리즘이 된다. 부분 문제가 캐시에 들어갈 만큼 작아지면 캐시 크기를 매개변수로 쓰지 않고도 효율적인 캐시 무관(cache-oblivious) 알고리즘이 된다(Frigo, Leiserson, Prokop, 1999). 호출 스택은 넘칠 수 있으므로 퀵 정렬은 중첩 호출이 log₂n 이하가 되게 구현할 수 있고, 스택·큐·우선순위 큐로 재귀를 대신해 다음에 풀 부분 문제를 더 자유롭게 고를 수도 있다. 분할·결합 비용이 선형이고 크기 n/p인 부분 문제가 p개이면 비용은 O(n logp n)이다.

    논문에는 이렇게 적는다

    • 분할 방식: 몇 개로, 어떤 기준으로 나누는지와 기저 사례의 크기를 적는다.
    • 결합 비용: 합치는 단계의 비용을 명시하고 점화식과 풀이(마스터 정리 등)를 제시한다.
    • 병렬화: 부분 문제를 장치에 어떻게 나누는지, 통신 비용과 부하 균형을 논한다.
    • 실험: 입력 크기별로 실행 시간이나 연산 횟수를 보고하고 이론 복잡도와 맞는지 확인한다.

    재귀 호출에는 비용이 들어 실제 구현에서는 기저 사례를 크게 잡는다. 예를 들어 퀵 정렬 라이브러리는 입력이 작아지면 삽입 정렬로 바꾸는 경우가 많다. 논문에는 이런 전환 기준도 함께 적는다.

    예시 문장

    아래 예문은 용어의 쓰임을 보이려고 만든 것으로, 실제 논문 문장이 아니다.

    "대용량 이미지 데이터를 다수의 부분 영역으로 분할한 뒤 병렬로 처리하는 분할정복(divide and conquer) 전략을 통해 전체 처리 시간을 단축하였다."

    이 문장은 하나의 크고 복잡한 작업을 여러 개의 작은 독립적인 작업으로 나누어 동시에 처리한 다음, 그 결과들을 합쳐서 최종 결과를 얻는 방식을 사용했다는 뜻이다. 정렬 알고리즘, 대규모 데이터 병렬 처리, 신호·이미지 처리 분야에서 계산 효율을 높이기 위해 자주 언급된다.

    "본 연구에서는 대규모 유전체 서열 정렬 문제를 다수의 하위 구간으로 분할정복 방식으로 나누어 처리함으로써 계산 시간을 크게 줄였다."

    생물정보학 분야에서도 긴 서열 데이터를 작은 구간으로 나누어 각각 분석한 뒤 결과를 통합하는 방식으로 분할정복 전략이 활용된다는 뜻이다.

    "제안하는 최적화 기법은 분할정복 방식으로 탐색 공간을 재귀적으로 축소하여 최적해에 더 빠르게 수렴하도록 설계되었다."

    최적화 알고리즘 연구에서는 전체 탐색 공간을 반복적으로 절반씩 좁혀나가며 계산 효율을 높이는 데에도 분할정복 개념이 응용된다는 의미이다.

    조금 더 깊게 보면

    분할정복 알고리즘의 효율성은 흔히 재귀 관계식(recurrence relation)을 세우고 이를 마스터 정리(Master Theorem) 같은 방법으로 분석해 시간 복잡도를 도출한다.

    나누는 단계와 합치는 단계에 드는 비용, 그리고 나뉜 부분 문제의 개수와 크기가 전체 성능을 좌우하며, 이 균형이 깨지면 오히려 비효율적인 경우도 있다. 병렬 컴퓨팅 맥락에서는 부분 문제들을 여러 프로세서나 노드에 분배하는 과정에서 통신 비용과 부하 분산(load balancing)이 추가로 고려해야 할 요소가 된다.

    주의할 점

    분할정복은 부분 문제들이 서로 겹치지 않고 독립적일 때 가장 효과적이다. 만약 나뉜 부분 문제들이 같은 계산을 반복해서 포함한다면, 그 결과를 저장해두고 재사용하는 동적계획법을 쓰는 편이 더 효율적일 수 있다. 또한 문제를 나누고 합치는 과정 자체에도 비용이 들기 때문에, 항상 탐욕 알고리즘보다 빠른 것은 아니다.

    헷갈리기 쉬운 용어

    기법문제를 어떻게 푸나적합한 경우
    분할정복독립적인 부분 문제로 나눠 각각 풀고 합침부분 문제가 겹치지 않을 때
    동적계획법부분 문제의 답을 저장해 재사용부분 문제가 겹칠 때
    탐욕 알고리즘매 단계 지금 가장 좋은 선택을 반복국소 최선이 전체 최선이 되는 구조일 때
    마스터 정리분할정복 점화식의 복잡도를 구하는 공식분석 도구
