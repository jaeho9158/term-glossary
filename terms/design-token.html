    디자인토큰 (design token)

    디자인시스템›디자인토큰
    디자인학
    한 줄 정의: 색상, 간격, 폰트 크기 등 디자인 결정 값을 코드에서 재사용 가능한 변수 형태로 정의하여 디자인과 개발 간 일관성을 유지하는 시스템 요소이다.

    쉽게 풀면

    색깔이나 크기 같은 디자인 값을 하나의 이름표가 붙은 변수로 만들어서, 여러 곳에서 똑같이 재사용할 수 있게 하는 것이에요.

    왜 중요한가

    디자인 토큰은 색, 간격, 글꼴 크기, 그림자 같은 디자인 결정을 이름 붙인 변수(예: color-primary-500)로 저장해 디자인 도구와 여러 플랫폼 코드에 동일하게 공급하는 방식입니다. 브랜드 색을 바꿀 때 토큰 하나를 수정하면 웹·iOS·Android에 동시에 반영되므로, 디자인 시스템의 일관성과 테마 전환(다크 모드)을 기술적으로 가능하게 하는 기반입니다. 디자인과 코드 사이의 값을 일치시켜 유지보수 효율을 크게 높이는 도구다.

    논문에서는 이렇게 쓰입니다

    "디자인토큰으로 정의된 'color-primary' 값을 변경하는 것만으로 전체 애플리케이션의 주요 색상이 일괄적으로 갱신되었다."

    중앙화된 변수 값 변경만으로 전체 시스템에 일관되게 반영된 디자인토큰 활용 사례를 설명한다.

    "다중 브랜드 제품군에 디자인토큰을 도입하여 색상과 여백 값을 코드 변수로 일원화하였다."

    이 문장은 디자인토큰이 여러 제품에 걸친 시각적 일관성을 코드 수준에서 유지하는 수단으로 쓰이는 사례를 보여준다.

    조금 더 깊게 보면

    토큰은 값 자체가 아니라 의미를 담은 이름 체계가 핵심이며, 원시 토큰(blue-500)과 의미 토큰(color-action-primary)을 층으로 나누어야 테마 교체가 가능합니다. 이름 체계 설계에 실패하면 토큰이 수천 개로 늘어 아무도 어느 것을 써야 할지 모르게 되는 문제가 실무에서 반복됩니다. Salesforce의 Lightning 팀(Jina Anne 등)이 2014년경 개념을 정식화했고, W3C 디자인 토큰 커뮤니티 그룹이 교환 포맷을 표준화하고 있습니다. 토큰은 값의 층위만 다루므로 컴포넌트 구조나 사용 지침은 별도로 필요합니다. 디자인 토큰은 색상 값이나 여백 수치를 직접 하드코딩하는 대신 이름 붙인 변수로 관리해, 하나의 토큰 값만 바꾸면 이를 참조하는 모든 화면에 일괄 반영되게 한다. 라이트 모드와 다크 모드처럼 테마가 여러 개일 때도 토큰 이름은 그대로 두고 값만 테마별로 바꿔 대응할 수 있다.

    주의할 점

    디자인토큰 체계가 지나치게 세분화되면 관리해야 할 변수의 수가 많아져 오히려 유지보수 복잡도가 증가할 수 있다.
