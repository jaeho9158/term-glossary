    크로스사이트 스크립팅 (XSS)

    컴퓨터과학·AI
    한 줄 정의: 공격자가 신뢰받는 웹사이트에 악성 스크립트 코드를 몰래 심어, 그 사이트를 방문한 다른 사용자의 브라우저에서 대신 실행되게 만드는 보안 취약점입니다.

    쉽게 풀면

    게시판에 누군가 "안녕하세요"라고 쓴 척하면서, 사실은 그 글 속에 몰래 작동하는 명령어를 숨겨 놓았다고 생각해 봅시다. 이 글을 다른 사람이 열어보는 순간, 숨겨진 명령어가 그 사람의 브라우저에서 자동으로 실행됩니다. 이렇게 되면 공격자는 피해자의 로그인 정보(쿠키)를 몰래 빼가거나, 피해자 계정으로 원치 않는 행동을 하게 만들 수 있습니다. 웹사이트가 사용자의 입력값(댓글, 검색어 등)을 제대로 걸러내지 않고 그대로 화면에 표시할 때 이런 공격이 가능해집니다.

    왜 중요한가

    크로스사이트 스크립팅은 오랫동안 웹 애플리케이션 취약점 목록에서 가장 흔하게 보고되는 유형 중 하나로 꼽혀 왔기 때문에, 웹 보안 연구에서 방어 기법과 탐지 시스템을 평가하는 대표적인 시험대로 사용됩니다. 사용자 입력이 그대로 웹페이지에 반영되는 현대 웹 애플리케이션의 구조적 특성상 프레임워크나 프런트엔드 기술이 바뀌어도 근본적인 위험이 계속 남아 있어, 새로운 웹 기술이 등장할 때마다 그에 맞춘 방어기법 연구가 재조명됩니다. 사용자의 세션 정보 탈취나 피싱으로 이어질 수 있어 웹 서비스의 신뢰성과 직결되는 문제로 다뤄집니다.

    핵심 정리

    크로스사이트 스크립팅(XSS)은 공격자가 웹 애플리케이션을 이용해, 보통 브라우저에서 실행되는 스크립트 형태의 악성 코드를 다른 사용자에게 보내는 공격입니다. OWASP는 이 취약점이 웹 애플리케이션이 사용자 입력을 검증하거나 인코딩하지 않고 출력에 쓰는 곳이면 어디서나 생길 수 있다고 설명합니다. 사용자의 브라우저는 그 스크립트를 믿어서는 안 된다는 것을 알 방법이 없어서, 믿는 사이트에서 온 것으로 보고 실행하며, 그 결과 해당 사이트와 관련된 쿠키·세션 토큰 같은 정보에 접근하거나 페이지 내용을 바꿀 수 있습니다. 취약점 분류 체계 CWE에서는 CWE-79, “웹 페이지 생성 중 입력의 부적절한 무해화(‘크로스사이트 스크립팅’)”로 분류합니다.

    OWASP는 유형을 크게 반사형(reflected)과 저장형(stored)으로 나누고, 덜 알려진 세 번째로 DOM 기반(DOM based) XSS를 설명합니다.

    예시로 보기

    • 저장형: 입력이 서버에 저장되었다가 다른 사용자의 페이지에 출력되어 실행됩니다(게시글·댓글 등).
    • 반사형: 요청에 담긴 입력이 응답에 그대로 반영되어 실행됩니다(검색어 등).
    • DOM 기반: 서버를 거치지 않고 브라우저의 스크립트가 입력을 처리하는 과정에서 생깁니다. Lekies 외(2013)는 대규모 웹사이트를 대상으로 이런 취약점 후보의 흐름을 탐지하는 연구를 했습니다.
    • 방어의 문헌: OWASP의 예방 지침은 출력 위치(HTML, 속성, 스크립트, CSS, URL)별 출력 인코딩과 콘텐츠 보안 정책(CSP)을 다룹니다(콘텐츠 보안 정책). Weinberger 외(2011)는 웹 프레임워크의 XSS 무해화(sanitization)를 체계적으로 분석했습니다.

    이 페이지는 개념을 설명하며, 공격 코드는 싣지 않습니다.

    자주 하는 오해

    • “입력만 걸러내면 끝”: 입력 검증만이 아니라 출력할 때의 맥락별 인코딩이 함께 논의됩니다.
    • “서버 문제만이다”: DOM 기반 XSS는 서버를 거치지 않고 브라우저 코드에서 발생합니다.
    • “SQL 인젝션과 같다”: 둘 다 신뢰할 수 없는 입력을 다루는 취약점이지만, XSS는 다른 사용자의 브라우저에서 실행되는 코드를 심고 SQL 인젝션은 데이터베이스 질의를 바꿉니다(SQL 인젝션).

    논문에서는 이렇게 쓰입니다

    예시 문장

    아래는 용어의 쓰임을 보여 주려고 만든 예시로, 실제 논문에서 가져온 문장이 아닙니다.

    "제안된 입력값 검증 필터는 저장형 및 반사형 크로스사이트 스크립팅(XSS) 공격을 각각 98.2%, 97.5%의 탐지율로 차단하였다."

    이 문장은 "게시글 등에 저장되어 나중에 실행되는 저장형 XSS와, 링크 클릭 즉시 실행되는 반사형 XSS를 실험적으로 탐지·차단한 성능을 수치로 제시했다"는 뜻입니다. 웹 보안, 취약점 탐지 시스템을 다루는 논문에서 대표적인 공격 유형으로 자주 다뤄집니다.

    "단일 페이지 애플리케이션 환경에서 발생하는 DOM 기반 XSS 취약점을 정적 분석과 동적 분석을 결합한 방식으로 탐지하는 도구를 제안하였다."

    서버를 거치지 않고 브라우저 내에서 자바스크립트 실행만으로 발생하는 DOM 기반 XSS를 다루는 최신 웹 보안 연구의 예시입니다.

    조금 더 깊게 보면

    XSS는 발생 위치와 방식에 따라 서버에 콘텐츠가 저장되어 실행되는 저장형, 요청 파라미터가 그대로 응답에 반영되어 실행되는 반사형, 그리고 서버를 거치지 않고 브라우저의 자바스크립트가 사용자 입력을 처리하는 과정에서 발생하는 DOM 기반 XSS로 구분됩니다. 방어 기법으로는 사용자 입력을 화면에 표시하기 전에 특수문자를 이스케이프 처리하는 출력 인코딩, 스크립트 실행을 제한하는 콘텐츠 보안 정책(CSP) 설정 등이 표준적으로 함께 논의되며, 논문에서는 이러한 방어기법을 우회하는 새로운 공격 벡터와 그에 대응하는 탐지 기법이 함께 다뤄지는 경우가 많습니다.

    주의할 점

    XSS는 웹페이지에 악성 "코드"를 심는 공격인 반면, SQL 인젝션은 데이터베이스에 보내는 "질의문"에 악성 코드를 심는 공격이라는 점에서 다릅니다. 둘 다 사용자 입력값을 제대로 검증하지 않아서 생기는 취약점이라는 공통점이 있지만, 공격이 실행되는 위치와 대상이 서로 다릅니다.

    헷갈리기 쉬운 용어

    용어공격이 실행되는 곳핵심
    크로스사이트 스크립팅다른 사용자의 브라우저신뢰하는 사이트를 통해 스크립트 실행
    SQL 인젝션서버의 데이터베이스질의문에 입력이 섞여 구조가 바뀜
    콘텐츠 보안 정책브라우저 쪽 방어실행할 수 있는 스크립트의 출처를 제한
