    트리테스팅 (Tree Testing)

    디자인학
    한 줄 정의: 시각적 디자인 없이 텍스트 기반 계층 구조만으로 사용자가 원하는 정보를 얼마나 잘 찾는지 검증하는 정보구조 평가 방법이다.

    쉽게 풀면

    디자인 없이 글자로만 된 메뉴 구조를 주고 사용자가 원하는 걸 잘 찾아가는지 테스트하는 방법이다. 예쁜 화면 없이 메뉴 이름과 구조만 글자로 보여 준 뒤, 사용자가 원하는 정보를 찾아 클릭해 보게 하는 방식으로 메뉴 구조 자체가 헷갈리지 않는지 확인하는 방법이다.

    왜 중요한가

    트리테스팅은 시각적 디자인 없이 사이트맵의 텍스트 계층 구조만으로 사용자가 특정 정보를 얼마나 쉽게 찾아내는지 측정하는 조사 기법으로, 정보 구조 자체의 논리성을 그래픽 요소의 영향 없이 순수하게 검증할 수 있다는 점에서 카드소팅과 함께 정보 구조 설계 단계에서 활용된다. 사이트 리뉴얼 전 기존 구조의 문제를 진단하는 데도 쓰인다.

    논문에서는 이렇게 쓰입니다

    이 연구는 트리테스팅을 통해 웹사이트 카테고리 구조 개편안의 탐색 성공률을 사전 검증하였다.

    정보구조 시안을 사전 검증해 실제 개발 전 문제를 발견한 연구 사례이다.

    "트리테스팅에서는 과제별 성공률과 함께 처음 선택한 상위 카테고리가 정답 경로였는지를 분석해 메뉴 명칭의 모호성을 진단하였다."

    최종 성공 여부뿐 아니라 사용자가 첫 클릭을 어디로 했는지를 보면 어떤 메뉴 이름이 헷갈리는지 찾을 수 있다는 뜻입니다.

    조금 더 깊게 보면

    트리테스팅은 텍스트 라벨의 명확성과 계층 구조만을 검증할 뿐 실제 시각적 레이아웃에서의 사용성까지 보장하지는 않아, 이후 단계에서 프로토타입 기반의 사용성테스트가 별도로 필요하다. 카드소팅이 사용자로부터 새로운 분류 구조를 도출하는 발산적 방법이라면 트리테스팅은 이미 만들어진 구조를 검증하는 수렴적 방법이라는 점에서 목적이 상반된다. 트리테스팅에서는 성공률뿐 아니라 사용자가 처음에 잘못된 상위 카테고리를 골랐다가 되돌아오는 비율(backtrack rate)도 함께 측정되며, 이 값이 높으면 최종 성공률이 같아도 실제 체감 난이도는 더 크다는 신호로 해석된다. 트리테스팅 결과에서 특정 과제의 성공률은 낮지만 소요 시간이 짧다면 사용자가 빠르게 포기했다는 뜻으로 해석되어, 성공률과 소요 시간을 함께 봐야 실패의 성격(헤매다 실패, 빠르게 포기)을 구분할 수 있다.

    주의할 점

    트리테스팅은 시각 디자인 요소가 배제된 상태에서 순수하게 구조만 평가하므로 시각적 단서에 의한 영향은 배제된다. 트리테스팅은 참여자가 실제 맥락 없이 과제 문장만 보고 카테고리를 고르므로, 실제 서비스에서 사용자가 갖는 배경지식이나 동기를 완전히 재현하지는 못한다는 한계를 감안해야 한다.

    관련 용어

    카드분류법 정보구조화 사이트맵 내비게이션패턴 사용성 테스트 레이아웃디자인 사용자흐름 아이콘디자인 마이크로인터랙션 시각적피드백
