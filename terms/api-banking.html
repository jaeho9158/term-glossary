    API뱅킹 (API Banking)

    재무·금융학
    한 줄 정의: 은행이 계좌 조회, 이체, 결제와 같은 핵심 금융 기능을 표준화된 응용프로그램인터페이스 형태로 외부 개발자와 기업에 개방하여, 제3자가 자신의 서비스에 은행 기능을 직접 연동할 수 있도록 하는 기술 체계이다.

    쉽게 풀면

    은행이 자신들의 이체나 조회 기능을 레고 블록처럼 표준화된 형태로 열어두어서, 다른 회사들이 자기 앱이나 서비스에 은행 기능을 쉽게 끼워 넣을 수 있게 해주는 방식이다.

    왜 중요한가

    카카오페이나 토스 같은 핀테크 기업이 은행 계좌정보를 자사 앱에서 조회·이체할 수 있게 해주는 기술적 기반으로, 오픈뱅킹 정책의 실행 수단이자 금융서비스 혁신의 기초 인프라로 다뤄진다. API 품질이 낮은 은행은 응답 지연이나 오류로 핀테크 서비스의 사용자 경험 전체를 저하시킬 수 있어, 최근에는 은행별 API 성능을 정량적으로 비교하는 벤치마크 조사도 이루어진다.

    핵심 정리

    • API뱅킹은 은행이 계좌 정보 조회나 결제 개시 같은 기능을 표준화된 API로 열어, 고객이 동의한 제3자가 그 기능을 쓰게 하는 기술 방식이다.
    • 은행은 보통 이 API를 고객용 인터넷뱅킹과 별도로 마련한다. 접근은 고객의 명시적 동의에 근거하며, 동의의 유효 기간과 접근 범위를 관리하는 것이 구현의 핵심 과제이다.
    • 유럽연합의 개정 결제서비스지침(PSD2)은 2015년 11월에 채택되어 2018년 1월 13일 발효했다. API를 제공하는 금융회사는 2019년 3월 14일부터 제3자 사업자가 시험해 볼 수 있게 해야 했고, 대부분의 전자결제에는 강력한 고객 인증이 요구된다.
    • 영국에서는 경쟁시장청(CMA)이 2016년 8월 최대 은행 9곳에 면허를 가진 신생 업체의 계좌 데이터 접근을 허용하라고 명령했고, 이 명령이 2018년 1월 13일 시행되었다.

    예시로 보기

    가계부 앱이 여러 은행 계좌의 거래 내역을 한 화면에 모아 보여 주는 서비스는 계좌정보 서비스(AISP)에 해당한다. 쇼핑몰이 고객의 은행 계좌에서 바로 결제금이 빠지도록 요청을 넣는 것은 결제지시 서비스(PISP)에 해당한다. 두 경우 모두 고객이 은행에서 동의 절차를 거치고, 앱은 고객의 인터넷뱅킹 비밀번호를 받지 않은 채 은행이 연 API로 요청한다.

    같은 오픈뱅킹 정책 아래에서도 은행마다 응답 속도, 문서화 수준, 호출 제한이 달라 핀테크 서비스의 안정성이 갈린다. 그래서 API 품질을 은행별로 비교하는 조사가 별도 연구 주제가 된다.

    자주 하는 오해

    • “API를 열면 데이터가 완전히 개방된다.” 어떤 기능을 어느 범위까지 열지는 규제와 은행의 정책이 정하며, API는 그 결정을 구현하는 수단이다.
    • “API뱅킹과 오픈뱅킹은 같은 말이다.” 오픈뱅킹은 데이터 개방을 다루는 정책·제도의 개념이고, API뱅킹은 그것을 실제로 연결하는 기술 방식이다.
    • “제3자 앱은 고객의 은행 비밀번호를 받아 접속한다.” 표준 API 방식은 고객 동의와 강력한 고객 인증을 거치며, 제3자 앱 해킹, 과도한 직원 접근 권한, 피싱이 위험 요인으로 꼽힌다.

    예시 문장

    아래 예문은 용어의 쓰임을 보이려고 만든 것으로, 실제 논문 문장이 아니다.

    Cortet, M., Rijks, T., & Nijland, S. (2016). PSD2: The Digital Transformation Accelerator for Banks. Journal of Payments Strategy & Systems.

    코르테 외 연구진은 유럽 결제서비스지침이 은행에 표준화된 API 개방을 의무화한 배경과 그에 따른 은행의 사업모델 변화를 분석하여, API 기반 개방이 은행을 단순한 계좌 보유자에서 금융 플랫폼 참여자로 전환시키는 계기가 되었음을 보였다.

    오픈뱅킹 API를 도입한 은행들은 제휴 핀테크 기업 수가 늘어나면서 신규 서비스 출시 속도가 빨라졌다는 조사 결과가 나왔다.

    은행이 자신의 데이터와 기능을 외부에 열어 주자, 여러 핀테크 기업과 협력해 새로운 서비스를 더 빨리 내놓을 수 있게 되었다는 뜻이다.

    간편결제 기업은 API뱅킹을 통해 은행의 이체 기능을 자사 앱의 결제 단계에 직접 연결하여, 사용자가 별도 창을 열지 않고도 계좌 인증을 마칠 수 있도록 설계하였다.

    조금 더 깊게 보면

    API뱅킹은 기술적 연동을 가능하게 할 뿐이고, 실제로 어떤 기능을 어느 범위까지 개방할지는 규제와 은행의 정책적 결정에 달려 있어 기술 도입 자체가 곧바로 완전한 데이터 개방을 의미하지는 않는다. API뱅킹은 개발자가 이용할 수 있는 문서화 수준, 응답 속도, 초당 호출 제한 같은 기술적 품질이 실제 서비스 안정성을 좌우하므로, 동일한 오픈뱅킹 정책 아래에서도 은행별 API 성숙도 차이가 핀테크 서비스 품질 격차로 이어진다.

    주의할 점

    오픈뱅킹이 규제와 정책의 관점에서 데이터 개방을 다루는 개념이라면, API뱅킹은 그러한 개방을 구현하는 구체적인 기술적 연동 방식 자체를 지칭한다는 점에서 서로 밀접하지만 층위가 다른 개념이다.

    오픈파이낸스개방 대상을 은행 계좌 밖의 금융 상품까지 넓힌 개념API뱅킹은 은행 기능에 초점을 둔다
    핀테크금융과 기술을 결합한 서비스와 기업API뱅킹의 주요 이용자이다
