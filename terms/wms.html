    웹지도서비스 (Web Map Service (WMS))

    지리학
    한 줄 정의: 인터넷을 통해 지도영상을 표준화된 방식으로 요청하고 제공받을 수 있게 하는 OGC 표준 웹서비스이다.

    쉽게 풀면

    인터넷에서 지도를 실시간으로 불러와 화면에 보여주는 표준 방식이다. 예를 들어 지도 서비스 서버에 요청을 보내면 필요한 지역의 지도 영상을 실시간으로 받아 화면에 표시한다.

    왜 중요한가

    국토지리정보원의 국토정보플랫폼처럼 여러 기관이 웹을 통해 공간정보를 공유·서비스할 때 활용되는 국제표준 규격으로, 서로 다른 GIS 소프트웨어 간의 상호운용성을 보장하는 공간정보인프라의 실무적 기반이다.

    WMS 표준 덕분에 서로 다른 기관이 제작한 지도서비스를 하나의 웹지도 위에 함께 겹쳐 표시할 수 있어 공간정보의 상호운용성이 크게 높아진다. WMS 표준의 보급은 여러 기관이 각자 만든 지도서비스를 이용자가 따로따로 접속할 필요 없이 한 화면에서 통합해 볼 수 있게 함으로써 공간정보 활용의 편의성을 크게 높였다.

    어떤 절차인가

    WMS(Web Map Service)는 OGC(Open Geospatial Consortium)가 정한 웹 표준으로, 클라이언트가 HTTP 요청으로 지도 이미지를 받아 오게 한다(de la Beaujardière, 2006; ISO 19128:2005). 기본 연산은 세 가지이다.

    • GetCapabilities: 서버가 제공하는 레이어, 좌표계, 영상 형식 등을 설명하는 문서를 받는다.
    • GetMap: 레이어(LAYERS), 스타일(STYLES), 좌표계(CRS), 영역(BBOX), 영상 크기(WIDTH·HEIGHT), 형식(FORMAT)을 지정해 지도 영상을 받는다.
    • GetFeatureInfo(선택): 영상의 한 지점에 있는 지물의 속성 정보를 받는다.

    WMS는 영상(래스터)을 돌려주므로 그 안의 지물을 직접 편집하거나 분석하는 데는 쓰기 어렵고, 지물 자체가 필요하면 WFS 같은 다른 서비스를 쓴다.

    WMS는 OGC 표준으로 1999년에 처음 공개되었고, 보통 지도 서버가 GIS 데이터베이스에서 생성한 지리참조 지도 영상을 HTTP로 제공한다. 버전은 1.0.0(2000년 4월), 1.1.0(2001년 6월), 1.1.1(2002년 1월), 1.3.0(2004년 1월)이다.

    • 필수 요청은 GetCapabilities(서비스 정보와 레이어)와 GetMap(크기·좌표계·스타일·형식을 지정한 지도 영상)이다. 선택 요청으로 좌표 위치의 속성을 조회하는 GetFeatureInfo, 레이어의 피처 유형을 돌려주는 DescribeLayer, 범례 영상을 돌려주는 GetLegendGraphic이 있다.
    • 서버는 보통 PNG, GIF, JPEG 같은 비트맵을 반환하며, 점·선·텍스트 같은 벡터 내용은 SVG나 WebCGM으로 보낼 수 있다.
    • 서버로는 GeoServer, MapServer, deegree, QGIS Server, ArcGIS Server 등이, 클라이언트로는 QGIS, OpenLayers, Leaflet.js, Google Earth 등이 WMS를 지원한다.
    • 관련 표준으로 웹 커버리지 서비스(WCS), 웹 피처 서비스(WFS), 타일 맵 서비스(TMS)가 있다.

    언제 쓰고 무엇을 얻나

    여러 기관이 각자 서버에 둔 지도를 한 화면에 겹쳐 보여 주려는 웹지도에서 쓰인다. 클라이언트는 데이터를 내려받지 않고 보이는 영역의 영상만 요청한다.

    작은 예(가상). 영역을 경도 126~130°E, 위도 34~38°N(EPSG:4326)으로 잡고 영상 폭을 1,024픽셀로 하면 가로·세로 범위가 같으므로 높이도 1,024픽셀(정사각형)이어야 모양이 왜곡되지 않는다. 픽셀 하나는 4/1,024 = 약 0.0039°이다. 요청 형태는 대략 .../wms?SERVICE=WMS&VERSION=1.3.0&REQUEST=GetMap&LAYERS=레이어명&STYLES=&CRS=EPSG:4326&BBOX=34,126,38,130&WIDTH=1024&HEIGHT=1024&FORMAT=image/png이다. 주의: WMS 1.3.0에서 EPSG:4326을 쓰면 BBOX의 축 순서가 (위도, 경도)이므로 1.1.1(경도, 위도)과 다르다. 서버 주소와 레이어명은 설명용이다.

    논문에는 이렇게 적는다

    • 서비스 제공자, WMS 버전, 사용한 레이어와 좌표계, 접속 시점을 적는다. 서비스 내용은 바뀔 수 있으므로 접속일을 남긴다.
    • “WMS를 통해 배경지도를 불러왔다”로 끝내지 말고, 영상(래스터) 서비스라는 한계와 필요한 경우 WFS 등 보완 서비스 여부를 적는다.
    • 상호운용성이 주제라면 GetCapabilities 응답으로 지원 좌표계·형식이 일치하는지 확인한 결과를 제시한다.

    예시 문장

    아래 예문은 용어의 쓰임을 보이려고 만든 것으로, 실제 논문 문장이 아니다.

    본 연구의 웹지도 애플리케이션은 WMS를 통해 국토지리정보원의 배경지도를 실시간으로 불러왔다.

    WMS는 지도 이미지를 표준 규격으로 전송하므로 서로 다른 GIS 소프트웨어 간에도 지도 레이어를 공유할 수 있다.

    공공 공간정보 기관의 WMS 서비스를 연동하여 웹지도 애플리케이션에 실시간 배경지도를 표시하였다.

    WMS는 지도를 이미지 형태로 전송하므로 사용자는 지도 자료를 직접 저장하지 않고도 실시간으로 지도를 활용할 수 있다.

    조금 더 깊게 보면

    WMS는 지도를 이미지(픽셀) 형태로 제공하는 방식이어서, 벡터 형태로 실제 객체 데이터를 내려받아 편집·분석까지 가능한 WFS(Web Feature Service)와는 제공하는 데이터의 성격과 활용 범위가 다르다.

    WMS는 요청한 지역과 축척에 맞춰 이미 렌더링된 지도 영상을 실시간으로 전송하는 방식으로 작동하며, 실제 도형·속성 데이터 자체를 주고받는 WFS(Web Feature Service)와 달리 지도를 시각적으로 표시하는 데 특화된 표준이다.

    예를 들어 한 웹지도 서비스가 국토지리정보원의 배경지도(WMS)와 다른 기관의 토지이용 현황도를 함께 겹쳐 표시할 수 있는 것은 이 표준 덕분이다.

    WMS는 지도 이미지를 픽셀 단위로 전송하므로 시각적 표시에는 적합하지만, 개별 지점의 속성은 선택적 연산인 GetFeatureInfo로 제한적으로만 조회할 수 있고, 도형·속성 데이터 자체를 받아 편집·분석하려면 WFS 같은 다른 표준이 필요하다.

    주의할 점

    WMS는 이미지 형태로 지도를 전달하므로 벡터 편집이나 속성질의가 필요한 경우에는 WFS 등 다른 서비스가 필요하다.

    헷갈리기 쉬운 용어

    서비스돌려주는 것용도
    WMS지도 영상정해진 영역의 그림을 겹쳐 보기
    WMTS미리 만든 타일 영상빠른 웹지도 배경(캐시 활용)
    WFS지물(벡터) 자료지물을 직접 조회·분석·편집

    수문학의 WMS(Watershed Modeling System)나 물류의 WMS(창고관리시스템)는 약어만 같은 다른 용어이다.
