    ATLAS.ti (ATLAS.ti)

    사회과학·경제학

    ✓ 출처 대조 2026-11-06

    한 줄 정의: 텍스트, 이미지, 오디오, 영상 등 다양한 형태의 질적 자료를 코딩하고 개념 간 네트워크로 시각화하여 분석할 수 있도록 지원하는 질적자료분석 소프트웨어.

    쉽게 풀면

    NVivo와 함께 질적 연구에서 널리 쓰이는 대표적인 프로그램이다. 텍스트뿐 아니라 사진, 음성, 영상 자료까지 코딩할 수 있고, 코딩한 개념들을 서로 연결해 시각적인 네트워크 지도로 만들어볼 수 있는 기능이 특징적이다. 이를 통해 개념들 사이의 관계를 눈으로 확인하며 이론을 발전시켜 나가는 데 도움을 준다.

    왜 중요한가

    질적 연구는 방대한 인터뷰·관찰·문헌 자료를 체계적으로 코딩하고 해석하는 과정이 핵심인데, 이를 수작업으로 하면 일관성 유지와 자료 관리가 매우 어렵다. ATLAS.ti 같은 도구는 코딩 결과를 구조화하고 개념 간 관계를 시각화해 근거이론이나 주제분석 같은 방법론의 신뢰성과 재현 가능성을 높여준다. 그래서 간호학, 교육학, 경영학 등 질적 방법을 활용하는 다양한 분야의 논문에서 방법론 절 도구로 자주 언급된다.

    어떤 절차인가

    ATLAS.ti에서 질적 자료 분석을 진행하는 일반적인 흐름은 다음과 같다(분석 방법에 따라 순서는 달라진다).

    1. 프로젝트 만들기: 연구 한 건당 프로젝트 파일 하나를 만들고, 인터뷰 녹취록·문서·사진·오디오·영상을 문서(document)로 불러온다.
    2. 인용(quotation) 선택: 의미 있는 대목(문장, 이미지 영역, 영상 구간)을 표시한다.
    3. 코드(code) 붙이기: 인용에 개념 이름표를 붙인다. 자료에서 귀납적으로 만들거나, 미리 정한 코드북(연역)을 쓴다.
    4. 묶기와 정리: 코드를 코드 그룹으로, 문서를 문서 그룹(예: 집단별)으로 묶어 비교 준비를 한다.
    5. 메모(memo) 작성: 해석과 분석 결정의 이유를 기록한다.
    6. 탐색과 시각화: 코드별 인용 모아 보기, 코드-문서 표, 코드 공출현, 개념 간 네트워크 보기로 패턴을 찾는다.
    7. 보고서 내보내기: 코드와 인용을 표로 출력해 논문 서술에 연결한다.

    언제 쓰고 무엇을 얻나

    • 언제 쓰나: 자료가 많거나 형태가 다양할 때, 여러 연구자가 같은 자료를 나누어 코딩할 때, 코딩 근거를 남겨 두어야 할 때 유용하다. 근거이론, 주제분석, 내용분석처럼 코딩이 핵심인 방법들의 작업 도구로 쓰인다.
    • 무엇을 얻나: 코드 기준 검색으로 해당 인용을 한꺼번에 모아 볼 수 있고, 코딩 수정 이력을 관리할 수 있으며, 연구자 간 코딩 일치도를 확인하는 기능도 제공된다. 시각화 결과는 해석을 돕는 자료이다.
    • 얻지 못하는 것: 프로그램이 주제나 이론을 대신 만들어 주지는 않는다. 코드 빈도가 높다고 곧 중요한 주제라는 뜻도 아니다. 해석과 타당성 판단은 연구자의 몫이다.
    • 유의할 점: 코딩 체계를 정하지 않고 코드를 늘리면 오히려 자료가 복잡해지므로, 코드북을 정의하고 정리하는 시간을 둔다. 이러한 도구를 통칭해 컴퓨터 지원 질적 자료 분석 소프트웨어(CAQDAS)라고 부른다.

    유래와 지원 범위. 토마스 무어가 베를린 공과대학의 ATLAS 프로젝트(1989~1992) 중에 시제품을 만들었고, 첫 상용판은 1993년에 나왔다고 한다. 텍스트뿐 아니라 이미지, 오디오, 영상, 지리공간 자료를 다루고, 윈도우·맥·모바일과 웹 기반 클라우드로도 쓸 수 있다. XML 내보내기를 지원해 프로그램 사이의 자료 교환에 쓰인다. 상용 소프트웨어이므로 논문에는 버전을 밝혀야 한다.

    논문에는 이렇게 적는다

    • 도구 정보: 소프트웨어 이름과 버전(예: ATLAS.ti 9)을 적는다. 도구는 방법 절에서 분석 방법의 보조 수단으로 쓴 것이라는 위치로 서술한다.
    • 분석 방법이 먼저: “근거이론의 개방코딩·축코딩 절차로 분석하였고, 코딩과 메모 관리에 ATLAS.ti를 사용하였다”처럼 분석 방법을 앞에 쓰고 도구를 뒤에 둔다.
    • 코딩 절차: 코더 수, 독립 코딩 여부, 불일치 해결 방법(협의 등), 코드북 개발 방법, 일치도 값(사용한 경우)을 적다.
    • 자료: 불러온 문서의 종류와 수(예: 심층면접 녹취록 12건)를 밝힌다.
    • 자동 기능 사용 여부: 자동 코딩이나 자동 요약 같은 기능을 썼다면 어떻게 썼고, 어떻게 검토했는지 적는다.

    가상의 서술 예: “면접 녹취록 12건을 ATLAS.ti 9에 불러와 두 연구자가 독립적으로 코딩한 뒤, 일치하지 않은 코드는 협의로 조정하였다.”

    조금 더 깊게 보면

    ATLAS.ti의 핵심 작업 단위는 자료(document)에 부여하는 코드(code)이며, 코드들은 상위 개념으로 묶이거나 서로 관계선으로 연결되어 네트워크 뷰(network view)를 이룬다.

    여러 코딩된 자료를 겹쳐 보며 빈도나 공출현 패턴을 확인하는 코드 매트릭스·코드 문서 테이블 같은 기능도 함께 쓰이며, 연구자의 해석 메모(memo)를 코드나 인용문에 연결해 분석 과정을 기록해두는 것이 일반적이다.

    다만 이런 시각화나 빈도 정보는 어디까지나 연구자의 해석을 보조하는 도구이며, 자동으로 이론적 결론을 산출해주지는 않는다는 점에 유의할 필요가 있다.

    주의할 점

    기능이 방대하여 학습곡선이 있으며, 코딩체계를 명확히 설계하지 않으면 오히려 자료가 복잡해질 수 있다.
